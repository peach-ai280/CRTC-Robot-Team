> 这一份是"能立刻干活"的路径。
> 原来那份 `编译与烧录指南.md` 讲的是 CubeIDE + CubeMX 图形化流程，那个也能用；
> 但 CubeMX 每次生成代码会重写 `main.c`，新手很容易被冲掉代码。

## 二、编译（四条命令，出四个固件）

```bash
cd C:/Users/hp/WorkBuddy/CRTC

python tools/build.py full      # 完整固件：手柄 + 底盘 + 机构 + 视觉
python tools/build.py motion    # 只测底盘运动（串口发指令，不需要手柄）
python tools/build.py arm       # 只测舵机/机械臂
python tools/build.py ps2       # 只测 PS2 手柄接线（★ 到手第一步，车不会动）
python tools/build.py vision    # 只测视觉串口协议（不需要摄像头）
python tools/build.py all       # 五个一起编
```

产物在 `firmware/build/<目标>/`：

| 文件 | 用途 |
|---|---|
| `firmware.elf` | CubeIDE 调试用（带符号） |
| `firmware.bin` | 裸二进制，烧到 **0x08000000** |
| `firmware.hex` | STM32CubeProgrammer 用 |
| `firmware.map` | 看 Flash / RAM 占用 |

本机实测占用（gcc 14.3.1，-Os）：

| 固件 | Flash(text+data) | RAM(bss+data) |
|---|---|---|
| full | 30.6 KB | 3.8 KB |
| motion | 22.0 KB | 3.6 KB |
| arm | 20.5 KB | 3.5 KB |
| vision | 19.1 KB | 3.5 KB |
| ps2 | 18.8 KB | 3.5 KB |

芯片是 64KB Flash / 20KB RAM，余量充足。

### 换编译器路径
如果你 CubeIDE 装在别处或版本不同，改 `tools/build.py` 里的 `TOOLS` 变量即可。

## 三、不编译也能查：两个自检脚本

不接硬件、不装库也能先跑一遍，把低级错误挡在烧录之前。

```bash
python tools/check_symbols.py                      # 符号/宏静态自检
C:/Users/hp/.workbuddy/binaries/python/envs/default/Scripts/python.exe tools/sim/run_sim.py
# 运动学离线验证（需要 unicorn，已装好）
```

- `check_symbols.py` —— 查"调用了没实现的函数""用了没定义的宏""声明了没实现"，
  覆盖所有本工程模块前缀（`Motor_` `Chassis_` `Servo_` `Arm_` `PS2_` `Sensor_`
  `Vision_` `Auto_` `App_` `Limit_` `Mecanum_`）。抓不到类型错误，那个得靠编译器。
- `run_sim.py` —— **在 ARM 模拟器里真跑 `mecanum.c` / `motor.c`**，不是重写一遍公式。
  它把四轮解算值、写进 `TIM4->CCRx` 的 PWM 比较值、正解反算的速度方向都读出来做判定。

### 模拟器跑出来的结论（本机实测）

```
纯前进    (+1, 0, 0)  四轮 [+0.850 +0.850 +0.850 +0.850]   max=0.850
纯左移    (0, +1, 0)  四轮 [-0.800 +0.800 +0.800 -0.800]   max=0.800
纯逆时针  (0, 0, +1)  四轮 [-0.474 +0.474 -0.474 +0.474]   max=0.474
斜走45°   (0.8,-0.8,0) 四轮 [+1.000 +0.030 +0.030 +1.000]  max=1.000（被归一化压住）
```

- 三个特例的四轮符号模式全部正确
- 任何工况下 `|轮速|` 都不超过 1.0 —— 归一化限幅生效
- 正解反算的方向角与指令角**完全一致**（误差 0.000°）—— 归一化确实保住了方向

**并且它抓出了一个真问题**：原来 `SPEED_GAIN_STRAFE=0.80` 比 `FORWARD=0.85` 小，
导致推 45° 斜走实际走 43.26°，走 2 米横移 6 厘米。已把两者改平，偏差归零。
详见 `config.h` 里那段注释（含横移效率的标定公式）。

## 四、烧录

### 用 CubeIDE 烧（推荐，最省事）
1. 打开 CubeIDE → `Run` → `Debug Configurations...`
2. 左侧 `STM32 Cortex-M C/C++ Application` 上右键 → New
3. 右侧 `C/C++ Application` 填 `firmware/build/full/firmware.elf`
4. `Debugger` 页确认 Interface 是 ST-Link（SWD）→ `Debug`
5. 进调试后按 `Resume (F8)` 即运行；断开调试器后程序仍留在 flash 里

### 用 STM32CubeProgrammer 烧
打开软件 → 连 ST-Link → 选 `firmware.hex` 或 `firmware.bin`
（选 bin 时起始地址必须填 `0x08000000`）→ `Start Programming`

## 五、四个测试固件怎么用（还有一个是纯看手柄数据的）

串口统一 **115200 / 8N1**。接 PA9(TX) PA10(RX)，用任意串口助手，发字符**不用回车**。

### 0. ps2 —— 只测手柄接线（`python tools/build.py ps2`）★ 建议第一个烧

**这个固件不初始化电机和舵机，车绝对不会动**，东西到手在桌子上就能把线接对。

接线（`firmware/Core/Inc/board.h` 里的定义）：
`VCC→3.3V`（**不能接 5V**）`GND→GND` `ATT→PB0` `CLK→PA5` `CMD→PA7` `DAT→PA6`，ACK 不接。

串口每 250ms 打一行，不用发任何指令：
```
[ ON ] mode=0x73 lost=0 | LX=   0 LY=   0 RX=   0 RY=   0 | -
[ ON ] mode=0x73 lost=0 | LX= 100 LY= -20 RX=  30 RY=   0 | ○ △
```

| 看到 | 判断 | 怎么办 |
|---|---|---|
| `[ ON ]` 且推摇杆数字会动 | ✅ 成了 | 装车 |
| 一直是 `[ OFF]` | 没连上 | 手柄有没有电 → VCC 是不是 3.3V → 线对不对 |
| `[ ON ]` 但 LX/LY 恒为 0 | **CMD / DAT 接反了**（最常见） | 把 PA6 和 PA7 那两根对调 |
| `mode=0x41` | 只进了数字模式 | 接收头断电重插一次 |

详细排查见 `D:\WorkBuddy\CRTC交付\PS2到手后怎么弄好_接线与自检.md`。

### 1. motion —— 底盘（`python tools/build.py motion`）

**安全前提：第一次上电务必把车架空**（两本书垫住，四轮离地）。

| 键 | 动作 |
|---|---|
| `w` / `s` | 前进 / 后退 |
| `a` / `d` | 左移 / 右移 |
| `q` / `e` | 原地逆 / 顺时针 |
| `z` | 斜走 45°（专门看归一化） |
| 空格 | 停 |
| `r` | 自动演示，每 1.5 秒换一个动作 |
| `+` / `-` | 油门档 ±0.1 |

打印形如：
```
cmd(+1.00,+0.00,+0.00) wheel[+0.85 +0.85 +0.85 +0.85] duty[0.88 0.12 0.88 0.12] vbat=7.38
```
**方向对不对，看 wheel 的符号**（判据见上表模拟器结论）。
`duty` 一列里 0.88 / 0.12 是成对的：DRV8833 是 PHASE/ENABLE 接法，
正转 duty=|v|，反转 duty=1-|v|，所以右侧两个轮（装反了）显示 0.12 属正常。

### 2. arm —— 机构（`python tools/build.py arm`）

| 键 | 动作 |
|---|---|
| `1`~`7` | 7 个预设姿态（收起 / 待命 / 地面取块 / 台阶取块 / 入仓 / 挑架 / 洞窟） |
| `i`/`k` `o`/`l` `p`/`;` | 夹爪 / 大臂 / 前铲 各 ±5° |
| `m` | 打印四个舵机当前角度 |

**听到"吱吱"声立刻往回收** —— 那是脉宽超行程在硬撑，会烧舵机。
调好姿态后按 `m` 抄角度，填回 `config.h` 的 `SERVO_*` 宏。

### 3. vision —— 视觉协议（`python tools/build.py vision`）

**不接摄像头也能测**：

| 键 | 动作 |
|---|---|
| `t` | 造一帧白色能量单元（cls=1, x=40） |
| `y` | 造一帧黄色能量核心（cls=2, 面积大到触发"已到位"） |
| `n` | 造一帧"没找到目标" |
| `p` | 连续打印 3 秒 |

```
vis cls=1 x=40 y=130 w=60 h=60 area=6000 | valid=1 turn=-0.264 | near=0
```
`turn` 是 P 控制器算出的转向量：负值 = 目标在画面左侧 = 车要往左转。
接上 K210 后直接发 14 字节帧即可，协议见 `Core/Inc/vision.h`。
