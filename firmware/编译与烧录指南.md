# 编译与烧录指南（STM32CubeIDE）

> 本文假定你已经在 CubeMX 里建好了一个 STM32F103C8T6 工程，
> 生成过一次代码（有 `Core/Src/main.c`、`Core/Inc/main.h`、`stm32f1xx_hal_msp.c` 等）。
> 不熟悉的话：File → New → STM32 Project → 选 `STM32F103C8T6` → 一路 Next → 生成代码。

---

## 1. 把固件放进工程

把本仓库的文件按下面的位置复制进去（**只复制文件，不要覆盖 `main.c`**）：

```
<你的工程>/
├── Core/
│   ├── Inc/
│   │   ├── app.h          ← 复制
│   │   ├── arm.h          ← 复制
│   │   ├── board.h        ← 复制
│   │   ├── config.h       ← 复制
│   │   ├── mecanum.h      ← 复制
│   │   ├── motor.h        ← 复制
│   │   ├── ps2.h          ← 复制
│   │   ├── sensor.h       ← 复制
│   │   ├── servo.h        ← 复制
│   │   ├── vision.h       ← 复制
│   │   └── auto_task.h    ← 复制
│   └── Src/
│       ├── app.c          ← 复制
│       ├── arm.c          ← 复制
│       ├── mecanum.c      ← 复制
│       ├── motor.c        ← 复制
│       ├── ps2.c          ← 复制
│       ├── sensor.c       ← 复制
│       ├── servo.c        ← 复制
│       ├── vision.c       ← 复制
│       └── auto_task.c    ← 复制
```

CubeIDE 会自动把 `Core/Src` 下的 `.c` 编进去，**不需要手动改 Makefile**。

## 2. CubeMX 配置清单（逐项对着设）

### 2.1 SYS / RCC

| 项 | 设置 |
|---|---|
| SYS → Debug | **Serial Wire**（一定要设！不设的话烧一次就锁死 JTAG） |
| SYS → Timebase Source | SysTick |
| RCC → High Speed Clock (HSE) | Crystal/Ceramic Resonator（核心板上有 8MHz 晶振） |
| Clock Configuration | HSE → PLL ×9 → **72MHz**；APB1 = 36MHz，APB2 = 72MHz |

> ⚠️ 定时器实际时钟：APB1 预分频 ≠1 时定时器时钟 ×2，
> 所以 TIM2/TIM4（挂 APB1）的实际时钟是 **72MHz**，不是 36MHz。
> 我们所有 PWM 参数都是按 72MHz 算的。

### 2.2 TIM2 —— 4 路舵机 PWM（50Hz）

| 项 | 值 |
|---|---|
| Clock Source | Internal Clock |
| Channel 1/2/3/4 | **PWM Generation CHx**（对应 PA0 / PA1 / PA2 / PA3） |
| Prescaler (PSC) | **71** |
| Counter Period (ARR) | **19999** |
| Pulse | 1500（初始值，随便） |
| CH Polarity | High |

计算：72MHz / (71+1) = 1MHz；1MHz / (19999+1) = **50Hz** ✓
比较寄存器直接填微秒数（500 ~ 2500）。

### 2.3 TIM4 —— 4 路电机 PWM（10kHz）

| 项 | 值 |
|---|---|
| Channel 1/2/3/4 | **PWM Generation CHx**（对应 PB6 / PB7 / PB8 / PB9） |
| Prescaler (PSC) | **0** |
| Counter Period (ARR) | **7199** |
| Pulse | 0 |
| CH Polarity | High |

计算：72MHz / 1 = 72MHz；72MHz / 7200 = **10kHz** ✓

> 改了这里的 ARR 就要同步改 `motor.c` 里的 `MOTOR_PWM_PERIOD`（默认 7199），
> 否则占空比全部算错。

### 2.4 SPI1 —— PS2 手柄

| 项 | 值 |
|---|---|
| Mode | **Full-Duplex Master** |
| Hardware NSS Signal | **Disable**（我们用软件片选 PB0） |
| Frame Format | Motorola |
| Data Size | 8 Bits |
| First Bit | **MSB First** |
| CPOL | **High** |
| CPHA | **2 Edge** |
| Baud Rate Prescaler | **256**（≈281kHz） |

引脚自动分配到 PA5(SCK) / PA6(MISO) / PA7(MOSI) —— **如果 CubeMX 分配到别的脚，手动改回来**。

### 2.5 USART1 —— 调试 + 视觉

| 项 | 值 |
|---|---|
| Mode | **Asynchronous** |
| Baud Rate | **115200** |
| Word Length | 8 Bits |
| Parity | None |
| Stop Bits | 1 |
| NVIC | **USART1 global interrupt → Enabled**（`USE_VISION=1` 时必开） |

引脚：PA9(TX) / PA10(RX)。

### 2.6 ADC1 —— 电池电压

| 项 | 值 |
|---|---|
| IN9 (PB1) | **IN9 Single-ended** |
| Clock Prescaler | PCLK2 / 6（≤14MHz） |
| Resolution | 12 Bits |
| Sampling Time | **239.5 Cycles**（分压电路阻抗大，采样时间要长） |

### 2.7 GPIO

| 引脚 | 模式 | 上/下拉 | 初始电平 | 用途 |
|---|---|---|---|---|
| PB0 | GPIO_Output | No pull | High | PS2 软件片选 |
| PB12 / PB13 / PB14 / PB15 | GPIO_Output | No pull | Low | 电机方向 ×4 |
| PB10 / PB11 | GPIO_Input | **Pull-up** | — | 对中限位开关 |
| PB5 | GPIO_Input | **Pull-up** | — | 按键 |
| PC13 | GPIO_Output | No pull | High | 板载 LED（低电平点亮） |
| PA8 | GPIO_Output | No pull | Low | 蜂鸣器（可选） |

> ⚠️ PB10/PB11 **必须设成 Pull-up**。微动开关是"按下接地"，
> 不上拉的话引脚浮空，读数会随机跳变，对中永远判定不了。

## 3. 改 `main.c`（只需要加 8 行）

`main.c` 里找 `/* USER CODE BEGIN 2 */`，加：

```c
  /* USER CODE BEGIN 2 */
  extern void App_Init(void);
  extern void App_Tick(void);
  App_Init();
  /* USER CODE END 2 */
```

找 `while (1)`，改成：

```c
  /* USER CODE BEGIN WHILE */
  while (1)
  {
    App_Tick();
    /* USER CODE END WHILE */

    /* USER CODE BEGIN 3 */
  }
  /* USER CODE END 3 */
```

> **为什么只加这几行**：CubeMX 每次 Generate Code 都会重写 `main.c`，
> 但 `/* USER CODE BEGIN ... */` 和 `/* USER CODE END ... */` 之间的内容**会被保留**。
> 把逻辑全放在 `app.c` 里，`main.c` 永远只有 glue code，重新生成不会丢东西。

## 4. 改串口接收回调（只有 `USE_VISION=1` 时需要）

在 `Core/Src/stm32f1xx_it.c` 或 `main.c` 里加：

```c
/* USER CODE BEGIN 0 */
extern void App_UartRxCallback(UART_HandleTypeDef *huart, uint8_t byte);
static uint8_t g_uart1_rx;
/* USER CODE END 0 */

void HAL_UART_RxCpltCallback(UART_HandleTypeDef *huart)
{
  /* USER CODE BEGIN HAL_UART_RxCpltCallback */
  if (huart->Instance == USART1)
  {
    App_UartRxCallback(huart, g_uart1_rx);
    HAL_UART_Receive_IT(&huart1, &g_uart1_rx, 1);
  }
  /* USER CODE END HAL_UART_RxCpltCallback */
}
```

并在 `/* USER CODE BEGIN 2 */` 里启动第一次接收：

```c
HAL_UART_Receive_IT(&huart1, &g_uart1_rx, 1);
```

`USE_VISION = 0` 时**整段不用加**，代码不会编译报错。

## 5. 链接器设置：必须加 `-u _printf_float`

`app.c` 里的 `LOG()` 用了 `vsnprintf` 打印浮点数（`%.2f`）。
Newlib-nano 默认**不支持** `%f`，不加这个标志会打印出空白或 `?`。

**设置位置**：
Project → Properties → C/C++ Build → Settings →
Tool Settings → **MCU GCC Linker → Miscellaneous → Other flags**
添加：

```
-u _printf_float
```

同时确认 `MCU Settings` 里 **Use float with printf from newlib-nano** 是勾选的
（有些 CubeIDE 版本是 `-u _printf_float` 和这个二选一，两个都设上更稳）。

## 6. 优化等级

| 阶段 | 建议 |
|---|---|
| 调试期 | `-O0` 或 `-Og`（断点准、变量看得见） |
| 比赛期 | `-O2`（跑得快，但别指望断点还能对得上） |

⚠️ `ps2.c` 里的 `ps2_delay_us()` 是靠 `__NOP()` 循环实现的。
`__NOP()` 在 CMSIS 里是 `__ASM volatile ("nop")`，**volatile 汇编不会被优化掉**，
所以即使在 `-O2` 下也能正常工作。但如果你自己改了延时函数，记得加 `volatile`。

## 7. 编译错误速查

| 报错 | 原因 | 解决 |
|---|---|---|
| `undefined reference to App_Init` | `app.c` 没被编进去 | 刷新工程（F5）；确认文件在 `Core/Src` |
| `hspi1 undeclared` | CubeMX 没开 SPI1 | 按 2.4 配置后重新 Generate |
| `htim4 undeclared` | 没开 TIM4 | 按 2.3 |
| `hadc1 undeclared` | 没开 ADC1 | 按 2.6 |
| `ADC_CHANNEL_9 undeclared` | ADC 通道没选 IN9 | 按 2.6 勾选 IN9 |
| `TIM_CHANNEL_4 undeclared` | TIM2/4 没开全部 4 个通道 | 4 个通道都要设成 PWM Generation |
| `conflicting types for HAL_SPI_TransmitReceive` | 没包含 `spi.h` | 确认 `main.h` 里 `#include "spi.h"` |
| 串口打印全是 `?` 或空 | 缺 `-u _printf_float` | 见第 5 节 |
| 程序跑飞 / 进 HardFault | 栈不够 or 数组越界 | 把 `Heap_Size` 提到 0x600、`Stack_Size` 提到 0x800（在 `startup_stm32f103xb.s` 或 linker 脚本里） |
| 烧录后 JTAG 连不上 | SYS→Debug 没设 Serial Wire | 按住复位键点下载，或用 `STM32CubeProgrammer` 全片擦除 |

## 8. 烧录步骤

1. ST-Link V2 接核心板：`SWDIO / SWCLK / GND / 3V3` 四根线
   （**不要接 ST-Link 的 5V**，核心板由自己的电池或 USB 供电）
2. CubeIDE → Run → Debug（或 Run → Run）
3. 第一次会弹 Debug Configuration，直接 OK
4. 烧完按板子上的 RESET

**两台车刷同一套代码，只改 `config.h` 里的 `ROBOT_ID`**：

```c
#define ROBOT_ID   1   // 1号机（桥行者）
#define ROBOT_ID   2   // 2号机（拾荒者）
```

> 目前两台车的固件行为完全一致，`ROBOT_ID` 只用于串口打印标识和后续的差异化。
> 如果后面要给两台车配不同的机构角度，就在 `config.h` 里加 `#if ROBOT_ID == 1 ... #else ... #endif`。

## 9. 第一次上电的检查顺序

1. **不插电池，只插 ST-Link**，看能不能识别芯片
2. 烧录成功 → 拔掉 ST-Link
3. 接电池 → 串口助手（115200）应该看到：

```
==== CRTC2026 ROBOT-1 BOOT ====
init done. mode=semi-auto
V=8.21 | btn=0000 | L(   0,   0) R(   0,   0)
  cmd v=(+0.00,+0.00) w=+0.00 | wheel +0.00 +0.00 +0.00 +0.00
  duty 0.00 0.00 0.00 0.00 | arm=25 grip=30 scoop=60
  limit L0 R0 | macro=0 step | mode=semi
```

4. 按手柄按键 → `btn` 变成非 0
5. 推摇杆 → `L(...)` 数值变化
6. **架空**后再推摇杆 → `wheel` 四个数非零、`duty` 非零、轮子转

全部通过才算硬件 OK，之后的调参见 `docs/调参指南.md`。
