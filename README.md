## 2026-09-20 环境搭建与立项

**做了什么**

本地装了 VSCode 和 STM32CubeIDE。物料按《CRTC 官方物资表》采购，
**无线继电器暂未购买**。

**为什么这么做**

- **VSCode + CubeIDE 的分工**：CubeIDE 负责建工程、配时钟树和外设、编译烧录；
  VSCode 负责写代码、写文档、管 Git。
  没走 VSCode + PlatformIO 的路线，因为 PlatformIO 对 STM32F1 + HAL + FreeRTOS
  的支持需要自己折腾框架配置，新手踩进去容易卡在环境问题而不是代码问题上。
  CubeIDE 虽然界面老，但 CubeMX 图形化配时钟树能省掉大量查手册的时间。
- **无线继电器**：手册 3.3.4 和附录第 6 条写明——
  "未通过中期测评的队伍无需购买无线继电器，通过中期测评的队伍需要购买"。
  所以在 10 月 19 日中期考核出结果之前不用买。
  **但一旦通过必须马上买**：手册规定检录时要查"10m 范围内遥控断电"功能，
  检测无误后还要把断电遥控器交给裁判保管，没这个东西上不了场。
  已列入待办，避免到 10 月底断货。

**今天的判断**

决定**先做底层运动层，机构（机械）代码后面补**。
依据是两层依赖是单向的：机构层需要运动层的舵机驱动，
而运动层不需要知道夹爪长什么样。既然单向就能单向先做。
接缝定死成一个接口：

```cpp
g_actions.request(ActionId::kGrab);   // 上层只说"要抓"，不说几号舵机转几度
```

## 2026-09-25 底层运动层骨架完成

**做了什么**

完成 C++ 版底层运动层，共 5 个模块：

| 模块 | 职责 |
|---|---|
| `mecanum` | 麦轮正逆运动学解算（纯数学，无硬件依赖） |
| `motor` | 4 路 TT 马达 + DRV8833 |
| `servo` | 6 路舵机 PWM + 缓动 |
| `ps2` | PS2 手柄 SPI 驱动 + 掉线检测 |
| `chassis` | 底盘运动层：解算 → 限幅 → 斜坡 → 下发 |
| `safety` | 上电门控 + 软启动 + 看门狗 |

**为什么用 C++ 而不是 C**

队里主算法的人要兼嵌入式，C++ 的类能把"硬件资源"和"算法"隔开：
`Chassis::setBody(vx, vy, wz)` 这种接口写算法的时候不用关心底层是几个 PWM 通道。
但刻意规避了 C++ 里不适合单片机的部分：不用堆、不用异常、不用 RTTI、不用 STL，
全局对象构造时也不碰硬件（构造只清零变量，真正的 `init()` 才操作外设）。

**已验证 / 未验证**

- 麦轮运动学公式**已在 PC 上验证**：`正解(逆解(v)) == v` 在 5 组工况下全部还原，
  横移和自旋的轮子转向符号也符合 X 型安装的预期。
- **代码尚未在硬件上编译运行**。下一步是建 CubeIDE 工程、接线、分级调试。

## 二、半自动机器人要做哪些模块，每个模块怎么做

半自动方案的控制过程是：

**人看场地、选择目标 → 手柄发指令 → STM32 控制底盘和机构 → 机器人收集并保留方块。**

推荐的实体结构是：

**四轮底盘＋前方收集机构＋抬升机构＋带防掉落结构的储物仓。**

可以把三个舵机安排成：

- **MG995：**抬升收集斗或短机械臂。
- **SG90①：**控制轻型夹爪或收集斗挡门。
- **SG90②：**控制储物仓入口门或锁扣。
这是建议分工，最终要根据实际负载决定。SG90 不适合承担重型长臂。

| **模块** | **具体怎么做** | **零基础需要学什么** | **做到什么程度算完成** |
| --- | --- | --- | --- |
| **1. 底盘与车架** | 固定四个 TT 电机、四个轮子；电池尽量放低；前部预留抓取位置，后部放储物仓；给线路和螺丝留检修空间 | 长宽高测量、重心、螺丝连接、零件干涉；后续学基础 CAD 装配 | 满载移动时不明显翘头，转向不卡住，尺寸合规 |
| **2. 供电与断电** | 一个电池组统一供电，再分路降压给电机、舵机、主控；预留官方无线继电器接口 | 电压、电流、功率、串并联、共地；万用表；降压模块和线材选型 | 电机启动、舵机抬起时主控不重启，线路不过热，遥控断电有效 |
| **3. STM32 主控** | 使用培训提供的工程，先让指示灯闪烁，再读取按钮、输出控制信号 | C 语言变量、判断、循环、函数、数组、结构体；GPIO、定时器、程序下载 | 能独立修改、下载程序，并知道程序运行到了哪一步 |
| **4. 电机驱动** | 每个 DRV8833 通常可独立驱动两个直流电机；四个电机配两个模块，逐个验证正反转和调速 | PWM、驱动器输入、通道对应、电机启动和堵转电流 | 四个轮子分别可控；急停后不会继续执行旧指令 |
| **5. 手柄与移动控制** | 读取 PS2 摇杆和按键，设置前进、转向、横移、慢速模式、机构动作；加入失联停车 | 手柄通信、摇杆死区、按键消抖、麦轮速度分配 | 能低速准确靠近方块；手柄断开后底盘停止 |
| **6. 抓取与抬升** | 先做单个方块的收集；夹稳或关门后抬起，再送到储物仓；加机械限位，避免舵机顶死 | 舵机 PWM、角度范围、力矩、杠杆、连杆；动作先后顺序 | 能从地面收集 40mm 方块，举起时不掉、不明显变形 |
| **7. 储物与防掉落** | 方块进入仓内后关闭入口，再把前端机构放下去拿第二块；使用挡板、弹性门或机械锁扣保留已有方块 | 仓体净尺寸、间隙、防卡设计、重力落料、锁扣原理 | 已有第一块时仍可收集第二块；移动和断电后能保住方块 |
| **8. 程序协调与测试** | 把动作写成“待机、夹取、抬升、入仓、复位”等状态；记录测试和故障 | 状态机、超时处理、简单调试日志、Git/Gitee、Markdown | 动作不会互相打架；异常能停止或复位；考核视频与文档齐全 |

这里有三个很容易踩的坑：

**第一，储物仓比复杂机械臂更值得优先做好。** 比赛按结束时携带的方块计分。只把方块推着走，或者抓到后又掉了，都不能代替可靠携带。对局结束还会断电，因此不要只靠舵机持续用力夹住所有方块。

**第二，官方小降压板不能默认带得动全部电机和舵机。** 要检查实际持续输出能力和启动峰值。主控信号可以控制舵机，但不能让舵机的大电流经过主控板的小电源接口。TT 电机也不能不看额定电压就接满电 8.4V。

**第三，麦轮的横移能力要靠正确安装和程序配合。** 四个轮子方向装错、四轮转速差异过大，都会走偏。初期先完成前后和转向，再调横移。

## 三、全自动机器人在此基础上，还要增加哪些模块

**全自动可以复用半自动车的供电、底盘、抓取、储物机构，但要把人的观察和决策变成传感器与程序。**

它需要形成完整过程：

**找到目标 → 判断怎么接近 → 移动并修正偏差 → 确认抓到 → 入仓 → 选择下一个目标 → 遇到问题自行处理。**

| **增加或加强的模块** | **建议怎么做** | **需要额外学什么** |
| --- | --- | --- |
| **1. 位置与方向估计** | 用编码器估算轮子转过多少，用陀螺仪估算朝向，再用墙面距离或已知地形修正误差 | 编码器脉冲、定时器计数、角度、坐标、误差累计、基础 PID |
| **2. 目标检测** | 入门版只处理指定区域，用距离传感器和入口检测判断目标；升级版用视觉识别黄色核心、方块轮廓 | 传感器读数、滤波、检测阈值；视觉版再学颜色阈值、轮廓、相机标定 |
| **3. 接近与对准** | 不断比较目标位置和夹爪中心，边走边修正；接近后降速，达到抓取距离停车 | 闭环控制、比例控制、距离与速度关系 |
| **4. 路线与任务选择** | 先做少量固定目标的路线和状态机；路线被挡住时等待、后退或换目标 | 地图表示、任务优先级、状态转移；复杂后再学 A* |
| **5. 障碍与边缘检测** | 前方检测障碍，下方检测高台边缘；不能只会避开正面障碍却从侧面掉下去 | 红外/测距传感器、安装视野、误检漏检、刹停距离 |
| **6. 抓取成功确认** | 用微动开关、对射传感器等确认方块进入；失败则重新对准或放弃 | 数字输入、消抖、成功条件、重试次数 |
| **7. 异常恢复与比赛管理** | 处理目标消失、卡住、储物仓满、传感器异常；设置动作超时和有限次数重试 | 超时机制、故障状态、看门狗、计时与日志 |

**不用一开始就学 ROS、SLAM、神经网络或复杂机械臂逆运动学。** 这个场地尺寸固定、地形固定，可以先用简单路线和传感器反馈完成有限任务。

但也不能把“前进两秒、转弯一秒、夹一下”当成可靠全自动。电池电量、轮子打滑、被别人挤动都会让它偏离原位置。

还需要注意：

- **规则没有保证存在可供循迹的连续黑线。** 场地图上的格子和道具定位标记，不等于循迹赛道。
- 白色方块放在白色地面上，单纯按“找白色”识别会有困难；黄色核心相对容易区分。
- STM32F103C8T6 适合电机控制和简单传感器处理，复杂视觉通常要另外的视觉模块。
- 想拿全自动倍率，需经组委会认定；能遥控，也能执行一次自动动作，仍不当然属于全自动。
- **中期基础考核包含 PS2 控制车体。** 建议保留调试遥控模式，并提前确认正式全自动认定时对模式切换的要求。
从得分看，全自动的收益没有大到可以忽略成功率：

| **每个方块** | **半自动** | **全自动** |
| --- | --- | --- |
| 白色能量单元 | 1.5 分 | 2 分 |
| 黄色能量核心 | 5 分 | 6 分 |

例如，半自动稳定拿到两个黄色核心是 **10 分**，全自动只拿到一个是 **6 分**。对新手来说，可靠性往往更有价值。

## 四、你们的三个进阶功能可以选哪些

官方没有规定必须做哪三个。每项从创新度、实现难度、完成度评分，单项最高 3 分，三项最高 9 分；**这不是直接给中期最终总分加 9 分。**

仅仅“能上坡”“能拿两块”“三个舵机转动”，不能当作合适的进阶功能重复申报。

我建议考虑下面三个方向。**它们是申报候选，不保证评委一定认可；最好先拿功能描述向组委会咨询。**

| **候选功能** | **具体怎么做** | **视频怎样证明** | **额外材料与估算** |
| --- | --- | --- | --- |
| **① 有检测和重试的一键收集** | 人把车开到目标附近，按一次键；机器人完成夹取、抬升、入仓、复位；通过传感器判断有没有收集成功，失败后有限次数重试 | 同时展示正常收集和故意放偏的情况，证明它会判断失败并恢复，不只是播放固定动作 | 入口检测、限位开关、支架，约 **5—20 元** |
| **② 自动分仓与满仓管理** | 用可转位储物仓或分流挡板，将方块送入不同仓位；记录已占用位置，自动切换空位，满仓后禁止继续塞入 | 连续收集多个方块，展示自动换仓和满仓处理；转向、倾斜及断电后不掉落 | 额外舵机、检测件、打印仓体，约 **15—40 元** |
| **③ 面向洞穴的可展开取物机构** | 做能伸入狭窄洞口的薄型夹持/托取机构，收回后转运入仓；尽量复用原来的抬升驱动 | 搭建接近规则尺寸的洞穴，连续展示伸入、取出、转运、收拢，不碰坏道具 | 打印导轨或连杆、轴、可能增加的舵机，约 **10—35 元** |

第三项针对规则里 **70×70×50mm 洞穴中的黄色核心**。取物端连同方块必须留出通行间隙，普通的大夹爪很可能伸不进去。道具本身是外部 40mm、内部镂空 20mm 的结构，也可以研究利用孔洞定位，但必须避免尖锐结构和损坏道具。

这里的进阶性在于**特殊空间取物、机构展开和转运的完整设计**，不能只把普通夹爪换个名字。

如果最后走全自动方向，可以用“**目标自主识别与对准**”替换第三项。但应和“一键收集”明确划分：一个负责找目标和移动对准，一个负责抓取确认和失败处理，避免把同一件事拆成两项申报。

## 七、哪些可以 3D 打印，哪些最好购买

| **零件** | **是否适合打印** | **建议** |
| --- | --- | --- |
| 储物仓、分隔板、导料槽 | **很适合** | 薄壁加加强筋，预留清理卡块的入口 |
| 夹爪外形、收集斗、挡门 | **适合** | 做圆角，接触面可加橡胶，不能有锐边 |
| 舵机支架、传感器支架 | **很适合** | 螺丝固定，留调节孔 |
| 电路板托架、防护罩、线夹 | **很适合** | 留散热和接线空间 |
| 洞穴取物端、滑块、导向件 | **适合试制** | 需要试配，滑动处预留间隙 |
| 短连杆、小摇臂 | **可以** | 主要受力方向避免拉开打印层；转轴用金属件 |
| 电池固定托架 | **可以** | 打印机械支撑，电触点仍使用可靠金属件 |
| 整块主底盘 | **可以但不优先** | 官方金属底盘便宜，耐冲击，先用现成底盘更省事 |
| 长悬臂、重要受力轴 | **不建议普通打印件直接承担** | 优先金属轴、板材，或经过验证的加强结构 |
| 电机、舵机、主控、驱动板、电池、继电器 | **不能用普通打印替代** | 需要购买或领取 |
| 麦克纳姆轮 | **理论上能做，不建议新手自制** | 滚子、轴、摩擦和装配要求高，买成品更合适 |
| 螺丝、螺母、轴承 | **应购买** | 用标准金属件 |
| 练习方块、洞穴模型 | **可以** | 按规则尺寸制作；训练方块应尽量接近官方形状和重量，不能自行替换比赛道具 |

打印材料可以这样选：

- **PLA：**适合最初验证形状，容易打印。
- **PETG：**可用于需要一定韧性的仓体、支架，但仍需做结构测试。
- **TPU：**适合缓冲垫、防滑接触面；没有条件时直接买橡胶片。
零基础机械同学至少要学会：**画草图、标尺寸、拉伸、打孔、圆角、装配检查、导出 STL、切片、支撑和打印方向。** 先打印一个舵机支架验证孔距，再打印整套机构，返工损失会小很多。

## 八、零基础应该按什么顺序学，你们五个人怎么分工

不需要先学完整个专业。每学一个知识点，就用一个小实验确认自己会用。

| **阶段** | **软件同学** | **机械同学** | **电气同学** | **全队验收目标** |
| --- | --- | --- | --- | --- |
| **1. 基础入门** | C 基础；程序下载；指示灯、串口输出 | 读尺寸、画布局草图、认识标准件 | 电压电流、万用表、极性、短路 | 每个人能解释整车怎样工作 |
| **2. 单件实验** | 单个电机调速；单个舵机转角；读取手柄 | 一个舵机支架、一个简单夹爪 | 降压供电、测电压、可靠接线 | 单件可控且供电正常 |
| **3. 整车基础** | 四轮控制、手柄按键、三个舵机控制 | 底盘布局、抬升、储物仓 | 多负载供电、线束固定 | 能行驶，三个舵机动作并保持 |
| **4. 完成基础考核** | 动作状态机、失联停车 | 连续收集、防掉落、尺寸与强度 | 满载运行和断电测试 | 拿第一块后还能拿第二块，通过 180mm 跌落展示 |
| **5. 进阶功能** | 检测、重试、分仓；有余力再做自动导航 | 特殊取物、仓体优化、打印迭代 | 加传感器，解决干扰和电流问题 | 功能能重复演示，不只是偶尔成功 |

你们现有分工可以保留，同时明确交付物：

- **软件 A：底层控制。**负责电机、舵机、手柄和故障停车，交付能被其他代码调用的控制函数。
- **软件 B：动作逻辑与文档。**负责一键收集、检测与重试、仓库和日志；自动化升级时再负责导航与目标判断。
- **机械 A：底盘与整机布局。**负责尺寸、重心、安装孔、线束空间和跌落后的结构检查。
- **机械 B：取物与存储。**负责夹取、抬升、入口门、储物仓和特殊取物机构。
- **电气：供电与连接。**负责电源分路、负载核算、焊接固定、无线断电和故障排查。
两名软件、两名机械仍然需要互相了解工作，避免只有一个人能修某个模块。
