## 2026-09-20 环境搭建与立项

**做了什么**

本地装了 VSCode 和 STM32CubeIDE。物料按《CRTC 官方物资表》采购，
**无线继电器暂未购买**。

**为什么这么做**

- **VSCode + CubeIDE 的分工**：CubeIDE 负责建工程、配时钟树和外设、编译烧录；
  VSCode 负责写代码、写文档、管 Git。
  没走 VSCode + PlatformIO 的路线，因为 PlatformIO 对 STM32F1 + HAL + FreeRTOS
  的支持需要自己折腾框架配置，新手踩进去容易卡在环境问题而不是代码问题上。
  CubeIDE 虽然界面老，但 CubeMX 图形化配时钟树能省掉大量查手册的时间。
- **无线继电器**：手册 3.3.4 和附录第 6 条写明——
  "未通过中期测评的队伍无需购买无线继电器，通过中期测评的队伍需要购买"。
  所以在 10 月 19 日中期考核出结果之前不用买。
  **但一旦通过必须马上买**：手册规定检录时要查"10m 范围内遥控断电"功能，
  检测无误后还要把断电遥控器交给裁判保管，没这个东西上不了场。
  已列入待办，避免到 10 月底断货。

**今天的判断**

决定**先做底层运动层，机构（机械）代码后面补**。
依据是两层依赖是单向的：机构层需要运动层的舵机驱动，
而运动层不需要知道夹爪长什么样。既然单向就能单向先做。
接缝定死成一个接口：

```cpp
g_actions.request(ActionId::kGrab);   // 上层只说"要抓"，不说几号舵机转几度
```

## 2026-09-25 底层运动层骨架完成

**做了什么**

完成 C++ 版底层运动层，共 5 个模块：

| 模块 | 职责 |
|---|---|
| `mecanum` | 麦轮正逆运动学解算（纯数学，无硬件依赖） |
| `motor` | 4 路 TT 马达 + DRV8833 |
| `servo` | 6 路舵机 PWM + 缓动 |
| `ps2` | PS2 手柄 SPI 驱动 + 掉线检测 |
| `chassis` | 底盘运动层：解算 → 限幅 → 斜坡 → 下发 |
| `safety` | 上电门控 + 软启动 + 看门狗 |

**为什么用 C++ 而不是 C**

队里主算法的人要兼嵌入式，C++ 的类能把"硬件资源"和"算法"隔开：
`Chassis::setBody(vx, vy, wz)` 这种接口写算法的时候不用关心底层是几个 PWM 通道。
但刻意规避了 C++ 里不适合单片机的部分：不用堆、不用异常、不用 RTTI、不用 STL，
全局对象构造时也不碰硬件（构造只清零变量，真正的 `init()` 才操作外设）。

**已验证 / 未验证**

- 麦轮运动学公式**已在 PC 上验证**：`正解(逆解(v)) == v` 在 5 组工况下全部还原，
  横移和自旋的轮子转向符号也符合 X 型安装的预期。
- **代码尚未在硬件上编译运行**。下一步是建 CubeIDE 工程、接线、分级调试。
