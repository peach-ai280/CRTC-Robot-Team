## 一、底盘全向运动与麦轮防滑

### 功能描述

用四个麦克纳姆轮实现全向移动：前后、左右平移、原地自转。硬指标有两条：

- 五种动作都得能做出来；
- **横移和斜走的时候，车不能自己偏航** —— 方向一偏，后面的对位、收集全白做。

### 开发历程

**第一步：先在纸上推运动学，不着急写代码。**

麦轮的辊子是斜 45° 装的，四个轮的转速组合能合成任意方向的速度。我们按 X 型布局（左前、右前、左后、右后四个轮各自斜向不同）手推了逆解公式：给一组(vx 前进, vy 横移, wz 自转)，算出四个轮各自该转多快。

推完才发现，光有公式不够 —— 真正的麻烦在"算出来的值超过 100% 怎么办"。

**第二步：踩到最经典的一个坑——横移时车自己转圈。**

最初的写法是给四个轮**各自**限幅：谁的转速超过 1，就把它截断到 1。看着很合理，实际是错的。

原因是：当横移速度给到比较大的时候，四个轮解算出来的值大小不一，有的轮超了 1 被截掉，有的没超原样保留 —— **四个轮之间的相对比例被破坏了**，合成出来的速度方向就歪了。表现出来就是"推的是正左，车却斜着走"，转弯时车还会自己画弧。

**第三步：解法——整体等比归一化，不逐轮截断。**

改成：先扫一遍四个轮，找出绝对值最大的那个；如果它超过 1，就让**四个轮同时**除以这个最大值。

这样比例永远不变，只是整体"降速"。方向严格保住，代价是速度慢一点 —— 这个交换完全值得。

> 这是我们这个周期**最重要的一次改动**。代码在 `mecanum.c` 的 `chassis_normalize()`，一共 10 行，但它是"车能走直"和"车走不直"的分界线。

**第四步：防滑四件套。**

麦轮的辊子是塑料的、接地面积又小，比普通橡胶轮更容易打滑，尤其起步和急转的时候。我们叠了四层：

| 措施 | 解决什么 | 实现在哪 |
|---|---|---|
| 加速度斜坡（加、减速分开设） | 起步别一脚踩到底，避免轮子空转 | `chassis_ramp()` |
| 死区（油门小于 0.18 当 0） | 摇杆回中不准，导致车"自己慢慢爬" | `stick_map()` |
| 起步助力 kick | 越过死区的第一下给个短促大电流，克服静摩擦 | `motor.c` |
| 高速限自转 | 速度越高，允许的自转上限越低，防甩尾 | `chassis_limit_yaw()` |

**为什么不做编码器闭环。** 编码器要另外买、要装、要标定，我们的时间不够。开环 + 把参数调好，对"收集方块"这个精度要求是够的。**代码里留了接口**（`USE_ENCODER` 宏），以后想加随时能加。

**核心代码就四个文件**，都在仓库里可以点开看：

| 文件 | 作用 |
|---|---|
| `firmware/Core/Src/mecanum.c` | 底盘四步管线 + 麦轮逆解 |
| `firmware/Core/Src/motor.c` | 单轮输出：死区 → 起步助力 → 电压补偿 |
| `firmware/Core/Inc/config.h` | 全部运动参数（速度、加速度、限幅、符号） |
| `firmware/Core/Src/test_motion.c` | 架空测试专用固件（串口发 w/a/s/d 直接控车） |

四步管线的调用顺序在 `Chassis_Update()` 里：斜坡 → 限自转 → 逆解 → 归一化 → 输出。

**第五步：培训现场的上坡测试，暴露出一个硬问题。**

在统一培训现场做上坡测试时发现：**麦轮底盘爬不上手册里那条 300mm 坡道**，同时感觉整体"没劲"、电机发热、像是电机扛不住。

回来把数据摆出来算了一遍，结论是这个组合本身就选得不够：

| 项 | 数值 | 来源 |
|---|---|---|
| 坡道角度 | 坡高 300mm、坡比 0.5 → **26.57°** | 手册 P16 |
| TT 马达额定电压 | **3~6V** | 厂商公开参数 |
| TT 马达堵转扭矩 | 0.8 kg·cm @6V | 同上 |
| 我们实际给的电压 | 标称 7.4V / 满电 8.4V | 2×18650 |
| 我们整车设计重量 | 1.09 kg | 分项累加 |

- **扭矩**：上坡需要的每轮扭矩约 `0.34 × 车重(kg)` kg·cm。按 1.09kg 算，每轮要 0.37 kg·cm、四轮合计 1.46；而 1:48 的 TT 马达**可持续输出约 0.2 kg·cm/轮（8.4V 下约 0.28）**，四轮合计 1.12 —— **差约 30%**。
- **摩擦**：要爬上 26.57°，摩擦系数必须 ≥ tan(26.57°) = **0.50**；麦轮在地胶上的实际摩擦系数大约就是 0.5~0.7，**几乎没有余量**，地上一有灰就打滑。
- **电压**：TT 马达额定只有 3~6V，我们用 7.4V 已经是**超压约 40%**，电流和发热按比例上升，塑料齿轮箱的寿命明显缩短 —— 这就是"电机承不住"的直接原因。
- **电流**：4 个电机堵转一瞬间要 6~8A。DRV8833 单通道峰值只有 2A，正好卡在边缘，一上坡就进限流保护，表现成"一冲一冲"。

**这里我们错了一次判断**：一开始以为是参数没调好。算完才确认，**这是硬件选型的问题，光调参数救不回来**；而且**加大功率的方向不是加电压（已经超标了），而是加扭矩、减损耗**。

**对策（已列入采购，待实车复测）：**

| 方向 | 做法 | 代价 |
|---|---|---|
| 加摩擦 | 麦轮辊子套 O 型橡胶圈 / 改配 60mm 橡胶轮 | 橡胶轮会失去横移能力 |
| 加扭矩 | 换 1:120 减速比的 TT 马达（扭矩 ×2.5） | 速度从约 0.88 m/s 降到约 0.35 m/s |
| 减损耗 | 换高倍率动力 18650；电机回路改 20~22AWG 硅胶线、绕开面包板；每个 DRV8833 并 470~1000µF | 只是钱和时间 |
| 不硬碰 | 战术上先拿地面与洞穴里的道具，非必要不上 300mm 高台 | — |

> 合规性我们专门查过：手册附录注 2 写明**新生组的官方物资表只是"官方推荐"**，可以购买表外的物资；基础功能里的"底盘运动"只要求"用 PS2 手柄控制底盘的**水平运动**"，**并没有强制必须用麦轮**。所以换电机、换轮子都在规则允许范围内。电源部分仍然遵守"单一供电、额定 ≤7.4V"，**不会上 3S 或双电池组**。

**当前状态**：⚠ **代码写完、离线仿真跑过；桌面上已经跑通 ST-LINK 连接，但整车运动参数仍未经实车标定。**
车轮、电机、底板到手后，所有参数（速度增益、加速度、死区）都要**靠实车重新标定**。
详细推导和调参对照表见 `docs/03_底盘运动与麦轮防滑.md`、`docs/调参指南.md`。

## 二、手柄遥控与运动控制输入

### 功能描述

用官方 PS2 无线手柄遥控机器人。除了"能控"，还有一条安全要求：**手柄一掉线，车必须立刻停下来**。

### 开发历程

**协议本身：SPI 模式 3。**

手柄通过 SPI 跟单片机通信。我们用的参数是 CPOL=High、CPHA=2Edge、分频 256（约 281kHz）。

分频为什么选这么大（也就是为什么这么慢）—— 便宜手柄在 500kHz 下会偶发丢帧。轮询一帧只要 0.26ms，在 5ms 的控制周期里只占 5%，**慢一点换来不丢帧，值得**。

**最折磨人的一个坑：DI / DO 接反，查了三个小时。**

现象是串口一直收不到任何按键数据，但接线按图接的。我们依次排除了：量接收器电压（正常）、换手柄（一样）、把 SPI 四种模式组合全试一遍（一样）。

最后用示波器看波形才发现——**MISO 上一一直是高电平**，说明我们的数据线接到了手柄的"数据输入"脚上。

根源是接收器的丝印是**站在手柄角度**命名的：

| 丝印 | 含义 | 该接 STM32 |
|---|---|---|
| DI | Data In（进手柄） | MOSI（PA7） |
| DO | Data Out（出手柄） | MISO（PA6） |

我们是站在单片机角度接的，正好反了。**教训写进代码注释了：PS2 连不上，先对调 PA6/PA7，十次有九次是这个。**

**进模拟量模式。**

手柄上电默认是数字模式，摇杆只有 0 和 255 两档，没法做速度控制。必须在初始化时进配置模式，把模拟量打开。注意**配置命令之间要有延时**——我们第一版没加延时，命令全被吞了，现象是"一直停在数字模式"。

**摇杆到速度的映射，做了两件事：**

- **死区**：摇杆回中不准（中位左右各偏几个数），小于死区的一律当 0，否则车会自己爬；
- **expo 曲线**：中间段更细腻、满舵不变。这样低速对位的时候好控，又不损失极速。

**掉线保护（这条是安全底线）。**

掉线时不能只是"不再更新指令" —— 那样车里会**保留最后一次的速度一直跑下去**，直到撞墙。必须显式清零：

```c
if (!PS2_Poll()) {
    lost_cnt++;
    if (lost_cnt > 25) {        /* 约 125ms */
        connected = 0;
        btn = 0;
        lx = ly = rx = ry = 0;  /* 关键：清掉残留摇杆量 */
    }
}
```

**没有串口怎么看状态。** 板载那颗 LED 顺手写了套状态机，不接串口也能判断故障在哪：

| LED 表现 | 含义 |
|---|---|
| 常亮 | 通了（模拟模式） |
| 每秒闪 2 下 | PA6 / PA7 接反了 |
| 每秒闪 1 下 | 对面没回应（接收器没插 / 手柄没开机） |
| 每秒闪 2 下（双闪） | 数字模式，需要断电重插 |
| 全灭 | 程序没跑起来 |

**当前状态**：⚠ **这是目前唯一在推进的一环。**
SWD 烧录链已经实测打通，正在接那 6 根线做桌面测试，**还没跑到"摇杆能控车"这一步**。
接线表、LED 判读、协议细节见 `docs/05_PS2手柄与遥控器.md`。

## 三、桌面调试与第一次实机联通

### 功能描述

搭一套能稳定"改代码 → 编译 → 烧进板子 → 看结果"的环境。这块不直接产出功能，但**它是上面两条能推进的前提**。

### 开发历程

**不用图形界面，全部脚本化。**

本机装了 STM32CubeIDE 2.2.0（它自带 ARM 编译器和烧录器），但我们**不进它的图形界面点来点去**，而是自己写了两个脚本：

- `tools/build.py` —— 一条命令编译出固件（本机没装 make，所以自己写构建脚本）；
- `tools/flash.py` —— 一条命令烧录，自动找到 CubeIDE 自带的烧录器。

好处是：改一行参数,敲一条命令就出固件，不用等 IDE 转圈。

**自制 HAL 兼容层。**

标准做法是用 ST 官方的 HAL 库 + CMSIS，但我们这套环境拿不到。于是我们**直接操作寄存器**，自己实现了业务代码用到的 20 来个 HAL 函数，**函数名和官方一模一样** —— 这样业务代码一个字不用改，将来拿到官方库也能一键切回去。用到了哪些开源东西，见 `docs/开源项目说明.md`。

**离线验证：在电脑上跑真实固件。**

我们用 ARM 模拟器在电脑上模拟一颗 Cortex-M3，直接把编译出来的**真实固件机器码**跑起来，看电机输出对不对。这样改一个参数不用每次都烧板子试。

**实测结果（2026-10-08）：**

```
ST-LINK SN  : E1007200D0D2139393740544
Voltage     : 3.21V
Device ID   : 0x410
Device name : STM32F101/F102/F103 Medium-density
NVM size    : 128 KBytes
[OK] 芯片连上了
```

**"电脑 → ST-LINK → SWD → 芯片"整条路是通的。** `3.21V` 那行说明板子确实在从 ST-LINK 取电，芯片被正常枚举。

**当前状态**：✅ 环境与烧录链已实测打通；⏳ 架空测试固件（`test_motion.c`）已就绪，等电机到手即可上电验证。

## 四、物资采购与成本

### 功能描述

这部分是我负责的。要做三件事：**把官方给的物资清点清楚**、**算出还缺什么**、**该买的买齐**，同时不违规、不浪费。

### 开发历程

**第一步：先把官方物资表逐条核一遍，知道"不用买什么"。**

手册附录的物资表一共 18 项、两台车合计 ¥353.48（每车 ¥176.74）。逐条看完有两个直接结论：

- 底板是**一体带马达孔**的金属折弯板 → **不用打印电机座**；
- 麦轮套装里**带 TT 马达联轴器** → **不用打印轮毂**。

这一条很重要：**说明在机械臂定稿之前，我一个 3D 打印件都不需要，切片和耗材一根都不用动。**

**第二步：算缺口，查出三个官方没覆盖的地方。**

| 缺口 | 情况 | 我们的做法 |
|---|---|---|
| **USB 转串口模块** | 官方 18 项里**完全没有** | 自购 CH340 模块（¥6~8）。看不到摇杆值、占空比、电池电压就没法标定 |
| **SG90 舵机数量** | 官方每车只给 2 个，而"舵机运动（多项）"要求**同一台车 3 个同时动** | 走"两台车的舵机集中到一台车上拍"，不额外花钱 |
| **舵机 5V 供电** | 官方每车只给 1 个降压模块，它还要同时喂单片机 | 补 1 个降压模块给舵机单独一路（**分路不算违规**，规则管的是电池那一层）+ 0.1µF 瓷片电容 |

**第三步：按"现在就要用"分层买，不一次性囤齐。**

因为机械臂还没定稿，我把清单分了三档：

| 档 | 内容 | 什么时候买 |
|---|---|---|
| **桌面测试** | USB 转串口、电烙铁套装、热缩管、加长杜邦线 | **现在**（桌测用） |
| **底盘装配** | M3 螺丝螺母（含 ×8）、尼龙扎带 2.5mm | **等电机到手**（焊马达线、拧到底板） |
| **机构装配** | Φ3 光轴、M2.5 自攻、拉簧、PLA 胶、平垫圈 | **等机械臂定稿**（现在一样不买） |

**明确不买的（都写清理由）：**

- **无线继电器** —— 手册原文"**通过中期测评的队伍需要购买**"，中期这一步不买，这 ¥27.6 先不花；
- **热熔胶枪** —— 手册结构规范第 1 条明写"尽量避免采用热熔胶"；
- **电机座 / 轮毂 / 联轴器** —— 官方物资已经给了。

**第四步：培训之后，采购单上多了一组"动力改装件"。**

上坡测试出问题之后（详见第一节第五步），采购方向跟着改了。这一组不是"想升级"，是**算完发现不够用**。
分两级：第一级是"几乎一定有效"的部分，只换便宜件、**不动结构、不改运动学、横移能力保住**；第二级备用。

| 级 | 想解决 | 买什么 | 怎么选 | 预算 |
|---|---|---|---|---|
| **一** | 扭矩不够 | TT 马达 **1:120** 单轴 | ⭐ 选**免焊线版**（省掉 8 个焊点）；必须**单轴**（双轴装不进原联轴器） | ¥28~40 |
| **一** | 摩擦不够 | 硅胶 **O 型圈** | 套在麦轮小辊子上，把摩擦系数从约 0.5 提到 0.65 | ¥5~8 |
| **一** | 瞬时掉压 | 高倍率动力 18650 | 持续放电 10A 以上 | ¥30~50 |
| **一** | 线阻压降 | 22AWG 硅胶软线 | 电机回路专用，**不走面包板** | ¥10 |
| **一** | 瞬时电流 | 470µF 电解电容 | 耐压 16V 以上，每个 DRV8833 一个 | ¥5 |
| 二 | 摩擦还不够 | 60mm 橡胶轮 | 要**同径 60mm**；换上就失去横移、且要改运动学 | ¥15~25 |

**★ 一个反直觉的结论：驱动板不用换。**
DRV8833 每通道持续 1.2A，现在的问题不是它不够，而是**电机工作在接近堵转的点**，一直在抽 1.5~2A。
换成 1:120 之后，同一个坡只需要电机出它额定范围内的力，**工作电流直接掉到 0.5~0.8A** → 1.2A 的通道能力绰绰有余。
同理，主控、下载器、底板、麦轮也全部保留。

同时把三条**可能白花钱**的路排除了：**不买 3S 电池、不买升压模块**（违反"单一供电、额定 ≤7.4V"），
**不买成品套件**。选择改装件的依据不是"哪个更强"，而是**"能不能算清楚够不够，以及规则允不允许"**。

⚠ 还查清了一条容易误判的规则：手册 P9 进阶功能的排除条款里，明确把"**机器人能够上坡**"列为
"**因为没统测试条件而没有添加进基础功能的较基础的功能**"，**不能拿来报进阶功能加分**。
所以爬坡是**战术手段**（能拿高台和台阶上的道具），不是得分项 —— 这决定了我们不为它过度投入。

**第五步：采购方向随"两车差异化"的确定，拆成了两批。**

在配件取舍上，我们确定了**两台车走差异化配置**（1 号车留麦轮、2 号车换橡胶轮）。
这一步的完整推论（规则依据、指标口径、隐藏因素、清单）写在**第五节**，那是一个独立的功能板块；
这里只记它对采购的影响：**改装件的采购被拆成"中期前"和"中期后"两批**，
中期前只买 1 号车用得上的（O 型圈等），1:120 马达和橡胶轮等到中期之后再买。

## 五、两车差异化配置与第二台车的改装

### 功能描述

我们队的两台车**不是两台一样的车，是两种车**：

- **1 号车（麦轮车）**—— 要它的**全向移动**。负责平地范围、以及一切需要**精细对位**的活：
  平地白块、桥下（净高 130mm）的白块、洞穴探杆、矮墙槽（31.5mm）的垂直对位。
- **2 号车（橡胶轮车）**—— 要它的**抓地力**。只走前后和转向，不去挤窄缝，
  专职**爬 26.57° 坡道、上 300mm 高台**，拿高台面的方块和中央高地的焦点能量核心。

这个分工的由来很简单：**没有任何一种轮子能同时"全向精确"和"能爬陡坡"。**

| | 麦轮 | 普通橡胶轮 |
|---|---|---|
| 全向横移 | ✅ 能 | ❌ 不能 |
| 在地胶上的摩擦系数 | 约 0.5~0.7 | 约 0.8~1.0 |
| 能否爬 26.57° 坡（需 μ≥0.50） | ⚠ **临界，几乎没余量** | ✅ 有余量 |

所以让两台车各拿一头，而不是把两台车都改成同一种。

### 开发历程

**第一步：确认"两台车不一样"这件事规则允不允许。**

在决定换轮之前，先把这个问题查清楚，免得白改。查完的结论是**允许**：

- **P6「机器人设定」**只按**启动区**定义 1 号 / 2 号机器人，**没有一个字**要求两台车同构型；
- **P9「考核指标一览」开头那行注**写的是"数量均以参赛队**所有机器人的总体数量**来计算"
  —— 如果强制两台车一样，这句话就没有存在的必要；
- 反过来，手册确实有两条硬要求：**两台车都要通过检录**（"所有参赛机器人均未通过赛前检录的队伍成绩直接判负"）、
  **每台各自满足通用规范**（每台 1 个供电模块、额定 ≤7.4V、能被无线继电器 10m 断电、初始尺寸 290×195×210）。

**第二步：确认中期的时间安排——中期只做 1 号车。**

我们的实际情况是：到 10-19 中期截止，能做出实物演示的只有 1 号车。所以安排是：

- **中期前**：集中把 1 号车（麦轮）做完整；
- **中期后**：确认过了中期，再动手做 2 号车的橡胶轮改装。

这不是"放弃 2 号车"，是**排优先级**。理由：中期考核**允许不产出实物演示**，
而且**做不到的指标不报就是，不倒扣分**，所以为了一台来不及的车去拖累 1 号车的调试，不划算。

**第三步（重要，改变了采购计划）：报"底盘运动（全部）"其实不需要换橡胶轮。**

又把 P9 的指标原文读了一遍，发现"底盘运动（全部）"的原文是：

> "能使用 PS2 手柄控制**全部车体**的水平运动（需保证车体与 PS2 手柄同时出镜或给出相关代码）"

它要求的是"**全部车体都能水平运动**"，**并没有要求第二台车有机械臂、有储仓、或者换了橡胶轮**。

于是得到两个结论：

1. **换橡胶轮是为了战术收益**（能上高台拿道具），**跟考核指标是两回事**。不换轮，指标 7 一样能报。
2. 只要**第二台车能通电、能用手柄走起来**（哪怕是个裸底盘），就可以报"底盘运动（全部）"。
   而第二台车的裸底盘——**底板、4 个马达、4 个麦轮、2 个 DRV8833、1 个降压模块，官方物资表按两台车的量都给齐了**，
   差的只是装配工时。

所以中期前的真实目标被修正为：**1 号车做完整 + 尽量让 2 号车的裸底盘也能跑**。
如果实在来不及，就**只报"底盘运动（单一）"**，不报的那一项不扣分。

**第四步：第二台车真的要换橡胶轮时，要额外买什么。**

官方物资表是**按两台车**给的（8 个 TT 马达、2 套麦轮、4 个 DRV8833、2 个降压模块），
所以换轮**不需要重买底盘和电控**，只需要补这些：

| 要买的东西 | 规格要求（照着选，别选错） | 为什么要它 | 估价 |
|---|---|---|---|
| TT 马达 **1:120** 单轴 ×4 | ⭐**免焊线版**（省掉 8 个焊点）；**必须单轴**（双轴装不进原联轴器） | 扭矩从 0.8 提到约 1.5 kg·cm | ¥12~20 |
| **60mm 橡胶轮** ×4 | ⭐**必须买"TT 马达专用 D 型孔"款**；外径**同 60mm** | 摩擦系数 0.5→0.9 | ¥12~20 |
| 高倍率**动力 18650** ×2 | 持续放电**10A 以上** | 堵转瞬间不掉压 | ¥30~50 |
| **22AWG 硅胶软线** 约 2m | 多股软线 | 电机回路专用，**不走面包板** | ¥10 |
| **470µF/25V** 电解电容 ×2 | 直插 | 2 号车两个 DRV8833 各并一个 | ¥3 |

**明确不用买的**（官方已经给足了，这是省钱的关键）：

- ❌ 金属底板、❌ DRV8833、❌ 降压模块、❌ 电池盒、❌ 充电器 —— 官方物资表**都是两台车的量**；
- ❌ ST-LINK、❌ PS2 手柄 —— **官方给了 2 个手柄**（见下面"隐藏因素"第 1 条）；
- ❌ 电机座 / 轮毂 —— 金属底板一体带马达孔；麦轮套装里**自带了 TT 马达联轴器**。

**第五步：把可能踩坑的地方一条条过一遍（这一步花的时间比前四步加起来还多）。**

| # | 隐藏因素 | 会怎么坑人 | 我们的结论 / 待办 |
|---|---|---|---|
| 1 | 手册写"确保信号的**发射源与接收源有且仅有一组**" | 一度以为"一队只能用一个手柄"，那两台车就没法分别控制 | ✅ **官方物资表给的是 2 个 PS2 手柄（¥45×2）** → 官方默认就是**每车一个**。那句话指的是"通信方式只能选一种（2.4G/蓝牙/WiFi/红外 四选一）"，不是限制手柄数量。**仍然建议在群里问一句留个底** |
| 2 | 重量上限 **2.0kg** 是"每台"还是"两台合计" | 影响配重和能不能上臂 | 原文在 P7「规格规范」下，与"初始长宽高"并列，且后面紧接"注：初始尺寸指每次对局正式开始时机器人的尺寸" → **是每台 2.0kg** |
| 3 | 成本 400 元是"每台"还是"合计" | 影响能不能买改装件 | 原文"**每支队伍**机器人造价总成本不推荐超过 400 元" → **两台车合计**。所以改装件要算进来（见下） |
| 4 | **麦轮和橡胶轮的"接地高度"可能不一样** | 麦轮是**斜辊子**结构，标称 60mm 不等于实际支撑高度；换成刚性圆轮后车会变高或变矮 | ⚠ **必须实测**：装了麦轮的车，量一次板面离地高度；换成橡胶轮后再量一次。**高度栈会跟着变** |

| 6 | 橡胶轮摩擦更大 = **更容易堵转** | 摩擦不再打滑之后，扭矩成了唯一下限，马达更容易憋住 | 已在计划内：**1:120 是必须项，不是可选项** |
| 7 | 1:120 减速比 = **速度掉一半**（0.88→约 0.35~0.40 m/s） | 2 号车跑一趟高台来回会慢 | 可接受：2 号车只跑坡道到高台这一段短距离。**如果后续觉得太慢，再考虑 1:90** |
| 8 | 两台车同时上场，**两个手柄会不会互相干扰** | 己方 2.4G 互扰 | 官方手柄是**可对频锁定款**，风险低；仍列为**待实测**（同时开机试一次） |
| 9 | **备用机器人也要过检录** | 备用车不合规会让上场车也受影响 | 中期阶段不做备用车，暂不涉及 |
| 10 | 手册要求**仓库名用队伍名称的英文或拼音** | 我们现在的仓库名是 `CRTC-Robot-Team`，**不是队伍名的英文/拼音形式** | ⚠ **待确认**：需要用报名时登记的队伍英文名，或改成拼音（如 `jiqiren-zongdongyuan`）。**这个要在中期提交链接之前定下来** |
| 11 | 塑料齿轮的**承受限度** | 1:48 是塑料齿轮，长期超压（8.4V vs 额定 6V）运行会磨 | 1 号车**巡航档占空比限到 0.75**（电机端约 6.3V，不超额定），只在需要冲刺时给满 |

## 六、机械臂的选型依据与开源方案复用

### 功能描述

两台车**各装一台机械臂，用同一款设计、同一套代码、同一张姿态表**，只是装车时按用途换末端：

| 车型 | 主战场 | 机械臂配置 | **用途** |
|---|---|---|---|
| **1 号车**（麦轮） | 平地、桥下、洞穴 | 标准臂 + 夹爪 | 抓地面白块（方块顶面离地 30mm）、伸进洞穴探黄块 |
| **2 号车**（橡胶轮） | 坡道之上、高台 | 标准臂 + 加长段 + 夹爪 | 够到 **250mm 高的物资架**、抓高台面和焦点的能量核心 |

⚠ **这一节写的是"选型依据和复用边界"，是给做结构的队友的输入**；
机械臂的具体尺寸、连杆、装配由他们定稿并在各自文档里叙述。

### 开发历程

**第一步：把硬需求先列出来（选型必须对着需求选，不是对着"哪个好看"选）。**

- 目标物：方块 **30×30×30mm**（白块和黄块**同规格**，所以**一个夹爪通吃**）；
- 最高要够到：**250mm**（物资架质心距地高度）；
- 最低要够到：地面方块顶面（离地 30mm）；
- **收起来以后**整车必须回到 ≤210mm 高、≤290×195 长宽（这是检录的"初始尺寸"）；
- 手上就这些舵机：**每车 1 个 MG995 + 2 个 SG90**（官方物资表 2 个 MG995、4 个 SG90，两台车分）。

**第二步：为什么选"2 自由度平面连杆臂"，而不是更复杂的。**

| 方案 | 重量 | 建模难度 | 调试难度 | 结论 |
|---|---|---|---|---|
| **2 自由度平面连杆**（肩 + 肘）+ 舵机爪 | 最轻 | 几块平板 + 舵机盘，**最好建模** | **一张固定姿态表就够**，不用逆解 | ✅ **选它** |
| 3~4 自由度复合臂 | 中等 | 复杂（多轴联动） | 要做逆解 | ❌ |
| 6 轴机械臂 | 重（逼近 2.0kg 上限） | 很难 | 逆解 + 逐轴标定 | ❌ |

**选它的理由，和"能不能做出来"没关系，和"能不能调稳"有关系**：
我们是新生队，时间是最大的约束。**2 自由度臂的所有动作都可以预标定成固定姿态**，
不需要实时解算，坏了一个姿态就只改一个数——这是"好调试"的全部含义。

**第三步：诚实地算一下它到底能有多准（这一条决定了我们不去报"精准抓取"）。**

舵机是**开环**的，没有任何角度回读：

| 环节 | 典型误差 |
|---|---|
| MG995 定位（金属齿轮，靠电位器） | ±1°~2° |
| SG90 定位（**塑料齿轮，虚位大**） | ±3°~5° |
| 换到臂端（臂长约 120mm，**1° ≈ 2.1mm**） | 累计 **±5~10mm** |
| 夹爪能容忍的偏差 | 约 **16mm**（喉口 46.4mm vs 方块对角线 42.4mm） |

结论：**能抓，但没有多次重复的把握**。所以策略是"机械对中优先"，不是"靠舵机精确"：

- ✅ **夹爪开口做成外八/喇叭口**，让方块自己滑进中心，把 ±8mm 误差吃掉；
- ✅ **固定姿态抓取**，不做中途解算；
- ✅ **靠底盘对位，不靠臂对位**——这也是 1 号车保留麦轮的另一个理由（它能横移微调）；
- ❌ **不要把"精准抓取"当进阶功能报**。手册要求进阶功能"可以明确由视频材料判断该指标是否被实际完成"，
  开环臂做不出可复现的精度，报上去反而扣分。

**第四步：开源方案调研，以及"能用多少"的边界。**

用户（队伍）明确允许复用 GitHub 上的公开模型和代码。我们把候选方案查了一遍：

| 开源方案 | 许可 | 尺寸/形态 | 我们打算怎么用 |
|---|---|---|---|
| **MeArm**（经典 4 自由度舵机臂） | MIT | 臂展约 200mm，底板固定式 | 参考它的**连杆几何**和**舵机姿态角标定方法** |
| **EEZYbotARM MK2**（3D 打印舵机臂） | CC BY-NC-SA | 体积偏大，件数多 | 参考它的**平行四边形结构保持末端姿态**的思路 |
| 通用"舵机 + 码盘 + 平板件"方案 | 无特定许可（公开教程） | 无固定尺寸 | **主要参考对象**：直接用舵机码盘做关节，平板做连杆 |

⚠ **关键边界：不能直接搬用现成 STL。**
我们的车长只剩 7mm 余量（283 vs 红线 290），高度栈也被轮径锁死。
现成模型是按它自己的底盘设计的，尺寸对不上，**硬搬会直接让整车超尺寸**。

所以我们的做法是：**参考开源的连杆原理和标定方法，尺寸全部自己出**。
如果后续真的直接采用了某个开源模型或代码，**必须回到本文档末尾（第七节）补充完整说明**，
这是手册的硬要求（"如果有使用开源项目用于机器人制作及代码编写的，应当在文档末尾完整说明"）。

**第五步："好调试"落到具体做法上。**

| 做法 | 说明 |
|---|---|
| **一张姿态表** | 所有动作 = 预标定的几个姿态（收起 / 地面抓 / 低位放 / 物资架 250mm / 洞穴探）。改一个数就是改一个姿态 |
| **一键收起（L1）** | 对应检录位和行驶位，保证整车回到 ≤210mm |
| **限位与超时** | `AUTO_PICK_HARD_TIMEOUT` 必须大于实际取块耗时，否则会误判失败 |
| **两台车共用一套参数** | 姿态表放 `config.h`，两台车编译同一个固件；只有加长段的那几个姿态值不同 |

**当前状态**：⚠ 机械臂由队里的结构组定稿。本文只提供**选型依据、精度边界和复用边界**，
具体尺寸以结构组的文档和 `mechanical/` 下的模型为准。

## 七、两台机器人的物块获取方式与运动学分工

### 功能描述

按前面的分工，两台车的物块获取方式不一样，这不是"顺手做两套"，是**场地逼出来的**：

| 车型 | 获取方式 | 自动化 | **负责的物块** |
|---|---|---|---|
| **1 号车**（麦轮） | **前铲抬块 + 吞噬入仓**：车头前铲带 20° 抬升斜面，贴地把方块铲起、顺势推进仓内 | **半自动**（×1.5 / ×1.25） | 平地白块、桥下白块、洞穴黄块——**数量和重复度最高** |
| **2 号车**（橡胶轮） | **机械爪抓取**：标准臂 + 夹爪，配合差速转向对位 | **半自动**（建议，见下） | 物资架黄块、中央焦点黄块、高台面白块——**位置最难、分值最高** |

两台车的**运动学内核不同**：1 号车是麦轮（能横移），2 号车是橡胶轮（不能横移，只能差速/滑移转向）。
代码是**同一份源文件**，差别只有一个编译宏。

### 开发历程

**第一步：为什么 1 号车不能"夹"，只能"推"。先算缝隙。**

场地上的方块不是散放的，很多卡在两片矮墙之间的槽里。手册 P16 写了两处矮墙的尺寸：

| 位置 | 矮墙规格 | 组内间距 | 方块边长 | **单边缝隙** |
|---|---|---|---|---|
| e8、d1 附属高台的矮墙 | 10×50×10mm | **31.5mm** | 30mm | **(31.5−30)/2 = 0.75mm** |
| 中央焦点基座的矮墙 | 10×60×10mm | **31.5mm** | 30mm | **0.75mm** |

**0.75mm。**任何爪指都塞不进去（最薄的打印件也在 2mm 以上）。
所以：

- ❌ **从侧面伸爪进槽里夹** —— 物理上不可能，别试了；
- ❌ **从上方垂直下爪** —— 也得塞进这 0.75mm，同样不现实（这修正了我们更早笔记里"只能垂直夹"的说法）；
- ✅ **从下往上抬 + 平推** —— **方块高 30mm、矮墙只有 10mm**，只要抬起来 20mm 以上就脱离限位了。**这是唯一合理的物理路线**。

**第二步：抬升要推多远？把楔形斜面算清楚。**

前铲做成一斜楔，往前推的时候把方块沿斜面抬起。要让方块底面越过 10mm 矮墙顶：

| 楔角 | 需要水平推进距离 |
|---|---|
| 15° | 37.3 mm |
| **20°** | **27.5 mm** |
| **25°** | **21.4 mm** |
| 30° | 17.3 mm |

选 **20°~25°**：行程合理（车前进 25mm 左右就够），又不像 30° 那样把方块"顶飞"出槽。

**第三步：三个硬约束，缺一个这个方案就是废件。**

**约束一：车长只剩 7mm，前铲绝对不能再加长。**

| 项 | 数值 |
|---|---|
| 当前车长（含铲） | 283 mm |
| 检录红线（初始尺寸） | **290 mm** |
| **余量** | **7 mm** |

直接把 20mm 的斜面接到车头外面 → 303mm，**超限 13mm，检录直接不合格**。
三条解法（**都不是加长**）：

- ✅ 把斜面**做进现有 283mm 内**——缩短铲斗平段，给斜面让位；
- ✅ 做成**折叠/伸缩铲**：检录时收起（尺寸合规），比赛时展开；
- ✅ 干脆不做独立斜面，用**带倾角的抬升铲**本身当斜面（平移到方块底下 → 抬起 → 正好是 20° 楔角）。

**约束二：斜面必须从离地 0mm 起步。**
附属高台只比地面高 20mm，矮墙立在地面上。如果斜面最前端离地太高，车头会直接**撞上矮墙侧面**而不是骑上去。
→ 斜面尖端必须贴地。

**约束三：附属高台只有 160mm 长、50mm 宽，容错极小。**
车要在这么窄的台上走位，还得把铲尖对准 0.75mm 级的缝。
→ 手动基本做不到，必须靠**机械对中（喇叭口导向）**；这也是**给 1 号车保留麦轮**的理由之一——它能横移微调。

**第四步：2 号车换橡胶轮之后，运动学的代码必须换。**

这是最容易出事、也最容易糊弄过去的一步。**橡胶轮和麦轮不能共用一套公式**：

```
麦轮逆解（1 号车，现有实现）：
  w_LF = vx − vy − (a+b)·ω
  w_RF = vx + vy + (a+b)·ω
  w_LB = vx + vy − (a+b)·ω
  w_RB = vx − vy + (a+b)·ω

差速/滑移转向（2 号车，橡胶轮）：
  w_左 = vx + K·ω          K = 半轮距 / 轮半径
  w_右 = vx − K·ω
```

**为什么"照抄麦轮"是灾难**：麦轮公式里那个 `vy` 项，在橡胶轮上**没有对应的物理自由度**。
如果照抄，手柄一推横移，四个轮子会**两两反向对打**——车原地抽搐、电流翻倍、位置一动不动，
而且**不会报错**，只会让人以为是"车没劲"。

**TURN_K 怎么来的**：车要原地转 ω（rad/s），左右轮心画的是半径等于"半轮距"的圆，
线速度 = ω × 半轮距（m/s）；但电机看的是**轮子转多快**（rad/s），所以再除以轮半径。
合起来 K = 半轮距 / 轮半径，**是个无单位的纯几何系数**。
⚠ 换轮子必须同步改轮半径，否则转向量直接算错。

**第五步：两套运动学怎么共用一份代码（这是报"底盘运动（全部）"的证据）。**

我们用**编译期开关**：

```c
/* firmware/Core/Inc/config.h */
#define CHASSIS_TYPE_MECANUM  0     /* 1 号车：麦轮，全向 */
#define CHASSIS_TYPE_DIFF     1     /* 2 号车：橡胶轮，差速 */
#ifndef CHASSIS_TYPE
  #define CHASSIS_TYPE        CHASSIS_TYPE_MECANUM
#endif
```

```c
/* cpp/src/chassis.cpp —— 外圈三步两台车完全相同，只有第三步换内核 */
void Chassis::kinematics(void)
{
#if CRTC_IS_DIFF()
    kinematicsDiff();        /* 橡胶轮：左右分组 */
#else
    kinematicsMecanum();     /* 麦轮：对角分组 */
#endif
}
```

**两台车用的是同一份源文件、同一份参数表**，只有运动学那一行不同。
这也是我们后面能坦然地报"底盘运动（全部）"的原因——**代码层面它就是一套，不是拿两台不同的车凑数**。

**第六步：验证。不是"看着对"，是四道检查都过了。**

（1）**编译**：C 版和 C++ 版都编出两套固件，**体积不同**（说明真的编进了不同代码）：

| 版本 | 1 号车（麦轮） | 2 号车（差速） |
|---|---|---|
| C（`firmware/`） | `text 21564` | `text 21060` |
| C++（`cpp/`） | `text 24848` | `text 24792` |

（2）**符号表互斥检查**：1 号车固件里**只有** `Chassis_*`，2 号车固件里**只有** `Diff_*`，互不出现：

```
B 车固件有 kinematicsDiff    : True
A 车固件有 kinematicsDiff    : False
A 车固件有 kinematicsMecanum : True
B 车固件有 kinematicsMecanum : False
B 车固件有 turnK             : True
A 车固件有 turnK             : False
```

（3）**模拟器数值对比**（同一份手柄输入，看四轮输出）：

| 输入 | 1 号车（麦轮） | 2 号车（橡胶轮差速） |
|---|---|---|
| 前进 vx=1 | 四轮 `+0.850` | 四轮 `+0.850` ✅ **完全相同** |
| **横移 vy=1** | `−0.850 +0.850 +0.850 −0.850`（**真的横移**） | **四轮全 0**（橡胶轮没有这个自由度） |
| 自转 wz=1 | `−0.474 +0.474 −0.474 +0.474`（**对角分组**） | `+1.000 −1.000 +1.000 −1.000`（**左右分组**）✅ |
| 斜走 vx=vy=0.707 | `0 +1 +1 0`（保住 45°） | 四轮同值，**只剩前进分量**（方向会偏，是丢 vy 的必然代价） |

两车自转的形式**一眼可辨**：麦轮是"左前/右后一组、右前/左后一组"的对角关系，
差速是"左侧一组、右侧一组"的左右关系。这是判断"到底有没有真的用上差速内核"最直接的办法。

（4）**模拟器自检全绿**：`python tools/sim/run_cpp_sim.py a` 和 `... b` 两个入口都是
`RESULT: ALL PASS (fail=0)`，共 30 多项断言。

**第七步：路上抓到的两个真坑（写下来给自己和队友看）。**

**坑一：新加的源文件不会被编译，但编译照样报"成功"。**

`tools/build.py` 的源文件列表是**显式写死的**，新文件不登记就**静默跳过**，
而且退出码是 0、`text` 段大小正常——**看起来一切正常**。
我们第一次编完就是这个情况，符号表里根本没有 `Diff_`。
→ 已登记新文件并在脚本里加了注释警告。
**纪律：加完新文件，必须查符号表确认它真的进去了。**

**坑二：编译期常量被优化器折叠，导致"换了宏但没换代码"。**

C++ 版最初把车型写成 `enum` + `const` 常量，然后用 `if (kChassisKind == kDiff)` 分派。
在 `-Os` 下编译器把它折叠成了一次**有符号比较**：1 号车（值 0）恰好走对，
**2 号车那份固件却仍然在跑麦轮公式**——编译不报错、符号表里两个内核都在、
只有跑数值才看得出来。
→ 改成**宏数值直接比**（`#if CRTC_IS_DIFF()`），优化器没有推理空间。
**并且把模拟器也改成必须单独编一份差速版**（`build_cpp.py sim_b`），
因为"用 1 号车那份 sim.elf 去测 2 号车的代码"是测不出来的。

**一个需要说明的规则判断**：机械组最初的设想是
"1 号车半自动（快）、2 号车不自动（手动）"。这**把奖励系数吃反了**。
手册 P17/P18：能量单元（白块，1 分）全自动 ×2、半自动 ×1.5；
**能量核心（黄块，4 分）全自动 ×1.5、半自动 ×1.25**。
乘数**作用在 4 分上的收益是作用在 1 分上的 4 倍**。

| 场景 | 得分 |
|---|---|
| 1 号车半自动拿 6 个白块 + 2 号车手动拿 2 个黄块 | 6×1.5 + 2×4 = **17 分** |
| **对调（黄块也给半自动）** | 6 + 2×4×1.25 = **16 分** |

**结论：2 号车也应该走半自动。**成本只是把半自动模式也对 2 号车编进去（同一套代码），
收益是每个黄块多 1 分。已在给机械组的反馈里提出。

**当前状态**：
- ✅ `firmware/Core/Src/chassis_diff.c`（C 版）+ `cpp/src/chassis.cpp` 的差速内核（C++ 版）都已落地；
- ✅ 两套都编译通过、符号表互斥、模拟器 30+ 项断言全绿；
- ✅ 编译/烧录流程见 `docs/` 下对应的操作说明；
- ⚠ **前铲斜面尚未做出实物**：车长只剩 7mm，必须先定"斜面做进现有长度内 / 折叠铲 / 抬升铲"三者之一，
  再出图打件；
- ⚠ 橡胶轮要等中期之后才换（中期只出 1 号车）；
- 【待实测】麦轮实际外径、装麦轮后的板面离地高度、TT 马达出轴规格（这四项决定 `TURN_K` 和高度栈要不要改）。

## 八、平地收集策略的反思：重新清点"平地上到底有几个方块"

### 功能描述

讨论"1 号车只做平地收集"时，我们必须先回答一个问题：
**平地上到底有几个方块是真正敞开的？** 结论比预想的少得多，直接改变了我们对 1 号车价值的判断。

### 开发历程

**第一步：把 18 个白块按"1 号车（麦轮、不上台阶）能不能碰"逐个过一遍。**

| 位置 | 形态 | 1 号车能拿吗 | 原因 |
|---|---|---|---|
| a8 | 地面角落 | ✅ | 纯平地 |
| h1 | 地面角落 | ✅ | 纯平地 |
| c4 | 桥下地面（净高 130） | ✅ | 纯平地，但要钻桥 |
| f5 | 桥下地面（净高 130） | ✅ | 纯平地，但要钻桥 |
| e8'、d1' 附属高台矮墙 | 距地 20mm | ❌ | **槽缝只有 0.75mm**，任何铲/爪都插不进 |
| e8、d1 台阶几何中心 | 150mm 高 | ❌ | 要上台阶 |
| e3、d6 台阶内侧 | 台阶上 | ❌ | 要上台阶 |
| 地图中心轴 4 个 | 中央高地脚下 | ❌ | 要爬 300mm |

**能稳定拿到的是 4 个。18 个白块里的 4 个。**

> **这条结论纠正了一个直觉**：我们原以为"平地收集"意味着"平地上很大一片都是我的"，
> 实际上场地是**障碍赛式的** —— 绝大多数白块被人为放在台阶上、槽里、高台上。
> **只靠"站在地面上够"这一条路，1 号车的得分天花板是 6 分（4 块 × 1.5）。**
>
> ⚠ **但"6 分"这个数是错的，第九节已经把它推翻了。** 这里表里的 4 个是"**纯地面**"的方块；
> 1 号车**本身就是从 h5 高台出发的**，它走桥就能摸到中央系统的白块和焦点黄块。
> **真实上限约 27 分，见下一节。** 保留此表是为了留下"我们怎么一步步想错的"的过程。

**第二步：算"堵门"（把方块留在场上不让对方拿）到底值多少分。**

统计口径必须先纠正：**方块在 0.75mm 的槽里，我方本来就拿不到**，
所以堵门的收益**不是"我多拿几分"，而是"对手少拿几分"**：

| 对手的自动化程度 | 对手本该拿 | 我方相对收益 |
|---|---|---|
| 半自动 | 2 × 1.5 | **3 分** |
| 全自动 | 2 × 2 | **4 分** |

**同时把坐标算出来，发现一件更要紧的事**（区块 300mm）：

| 位置 | 坐标 | 距谁近 |
|---|---|---|
| a1（红方 2 号启动区） | x=150, y=150 | — |
| **d1'**（堵门点 1） | **x=1050, y=150** | **离 a1 只有 900mm** |
| h8（蓝方 2 号启动区） | x=2250, y=2250 | — |
| **e8'**（堵门点 2） | **x=1350, y=2250** | **离 h8 只有 900mm** |
| h5（我方 1 号启动区） | x=2250, y=1350 | 到 d1' 约 **2376mm**、到 e8' 约 **1782mm** |

> **这两个"堵门点"，正好在对手 2 号车的家门口。**
> **我方车要跑 1.8~2.4 米过去，对手只需要动 900mm。堵门的人比被堵的人路更远。**

**第三步：发现一条规则层面的硬伤。**

手册的**一局结束条件**里有一条：**"一方全部机器人 1 分钟内无任何运动与机构活动"**。
而"堵门"这个动作本质上就是让车停在原地不动 ——
**停满 60 秒 = 主动触发自己的判负条件。** 这是这套战术最致命的规则风险。

**结论与对策**：
- 堵门**降级为备选**（只在比分领先时的最后 2 分钟顺手用），**不作为主战术**；
  ★ 而且第九节重算后，**1 号车的正经任务有 27 分要做完，根本没有时间去堵门** —— 这条更坚定了降级；
- 单次堵门 **≤40 秒**，且期间让某个机构**间歇动作**（例如储仓门每 10 秒开合一次），
  这样不满足"无任何运动**与**机构活动"的判负前提；
- **不为了堵门绕远路**，只做收集路线上的"顺手挡"。

**第四步：由此推出 1 号车末端的定案 —— 用「铲」，不用「爪」。**

这一步我们其实**早就有实测数据**（见 `docs/02_机械结构与3D打印.md`）：

| 版本 | 现象 | 结果 |
|---|---|---|
| v1：铲前缘是 **6mm 厚垂直墙** | 方块被一直**推到墙角**，就是上不来 | 成功率 **0** |
| v2：前缘倒成 **30° 斜面**（倒角约 10mm） | 方块被铲上车 | 成功率 **约 70%** |
| 侧向导板张开 **60° 喇叭口** | 斜撞弹开的方块被导流回中间 | 修掉剩余失败的主要原因 |

角度纪律：**>45° 太陡方块上不来、唇部易断；<20° 唇部太长会翘曲。30° 是实测出来的最优解。**

> **所以 1 号车的收集方案是**：**贴地前铲（前缘 30° 倒角）+ 两侧 60° 固定喇叭口导板**。
> **不做车头外接斜面**（车长 283 vs 红线 290，**只剩 7mm**，外接必超标），
> **不做可开合侧板**（多一个舵机 = 多一个故障点 + 多一路 5V 负载；
> 而喇叭口的收益固定角度就能拿到 90%）。
> 喉口按对角线算：`THROAT = CUBE_DIAG + 4 = 42.4 + 4 = **46.4mm**`，**一次只过一个方块**。

**第五步：1 号车"3 个舵机"的用途分配（这是中期指标 5 的硬需求）。**

| 舵机 | 用途 | 一举两得 |
|---|---|---|
| 舵机 1 | 前铲抬升（铲进去后抬起，防掉） | 收集功能 |
| 舵机 2 | **储仓门开合** | ★ 同时服务"方块携带"指标 |
| 舵机 3 | 视觉云台 / 侧导板 | 收集功能 |

⚠ **注意**：此处原写"导板"用舵机，第九节已改口 —— **导板用固定 60° 喇叭口，不占舵机**，
省下的这一路留给**洞穴探杆**（洞穴黄块 2 个值 10 分，是 1 号车最重的一块收入）。

⚠ **3 个舵机同时动会拉塌 5V**：我们实测 **MG995 启动/堵转电流到 1.2A**，
一把 MG995 转动就能让 STM32 复位（见 `docs/04_电源硬件与焊接.md`）。
代码里已有"**同一时刻只动一个舵机**"的串行机制 ——
**这正好也是指标 5 要求"非初始状态下保持相对静止"的天然条件**：不动的舵机就是静止的。

## 九、重算两车的任务量：纠正"平地收集只是边角料"的误判

### 功能描述

第八节得出结论"平地上只有 4 个白块是敞开的"之后，机械组立刻提了一个反问：
**"那全部压力不都压到 2 号车身上了？风险太大了。"**

这个反问是对的，而且它暴露出**我们自己前一节的判断有误** ——
我们当时只数了"**纯地面**"的方块，**漏掉了 1 号车从 h5 高台出发、沿桥就能摸到的东西**。
这一节把两车的任务量重新算一遍，结论是：**1 号车不是边角料车，它的任务是全场最重的那一份。**

### 开发历程

**第一步：先承认误判在哪。**

第八节那张表只回答了一个问题："**不上台阶、站在地上，能拿到几个？**"答案是 4 个。
但 1 号车的**出发点本身就在 300mm 高台上**（h5），它可以**在台上跑**——
"平地收集"不等于"只能在地面收集"。所以那张表**低估了 1 号车**。

**第二步：把 1 号车"从 h5 出发、不下高台系统"能碰到的东西全部列出。**

| 目标 | 怎么够到 | 分值 |
|---|---|---|
| a8、h1、c4、f5 四个地面白块 | 从 h5 下到地面（有坡道 h3/h4），或自 a4 方向绕 | 4 × 1.5 = **6** |
| **中央高台面上的白块** | h5 → 桥 f5/g5 → e5，**全程走桥，不爬坡** | 4 × 1.5 = **6** |
| **中央焦点黄块**（1 个） | h5 → 桥 → 中央高地中心 | 4 × 1.25 = **5** |
| **d1、e8 洞穴里的黄块**（2 个） | 洞口在地面、开口向外，车头贴进去就能探 | 2 × 5 = **10** |
| **合计** | | **约 27 分** |

> **1 号车的上限从"6 分"跳到"27 分"。** 差的那 21 分，全是我们**没算"它能走桥"**这一条。

**第三步：2 号车（橡胶轮、爬坡走位）的实际任务。**

| 目标 | 怎么够到 | 分值 |
|---|---|---|
| e3、d6 物资架黄块（2 个，质心距地 250mm） | 上 150mm 台阶，用机械爪从架上取 | 2 × 5 = **10** |
| 高台面上的白块（台阶上、中央高地边缘） | 爬坡上高台 | 4 × 1.5 = **6** |
| **合计** | | **约 16 分** |

**第四步：三种分工的对比（这才是回答"风险"的正确方式）。**

| 方案 | 1 号车 | 2 号车 | 总分 | **单台最大占比** |
|---|---|---|---|---|
| A：全压一台车（机械组担心的那种） | 0 | 33 | 33 | **100%** ⚠ |
| B：我们上一轮的说法（1 号车只扫平地） | 6 | 24 | 30 | **80%** ⚠ |
| **C：按上表重新分工（本节结论）** | **27** | **16** | **43** | **63%** |

**结论：真正的风险不是"平地上方块少"，而是我们上一轮**自己**把 1 号车的任务砍到了 6 分。**
按本节重算之后：
- 两车任务量是 **27 : 16**，负担比从 80:20 降到 63:37 —— **单台车不再"输一台就崩盘"**；
- **总分从 30 涨到 43**（因为把"桥"和"洞穴"这两条路算进来了），**离理论上限 66 更近了**；
- **2 号车的任务反而变简单了**：它只需要"**爬上去 + 用爪取物资架**"这一件事，
  不用再指望它把白块也扫一遍。**它现在是专精车，不是主力车。**

**第五步：这个新分工对两车设计的影响（要同步给机械组的）。**

| | 1 号车 | 2 号车 |
|---|---|---|
| 末端 | 前铲（30° 斜面）+ 固定喇叭口导板 | 机械臂 + 夹爪（原方案不变） |
| **必须能下高台** | ★ 有（h3/h4 坡道下到地面，再自己回来） | 不需要 |
| 舵机需求 | 铲抬升 + 储仓门 + 导板 = **3 个**（满足指标 5） | 大臂 + 夹爪 + 腕 = 3 个（**官方只给每车 2 个 SG90，需另配**） |
| 任务重心 | **数量**（白块 + 洞穴黄块，重复动作多） | **精度**（物资架取块，位置高、容错小） |

> ⚠ **一个必须提醒机械组的点**：方案 C 让 1 号车**必须能从高台下来再上去**。
> 我们查了一下，h5 到地面有 h3+h4 坡道（26.57°），麦轮下坡没问题，
> **但上坡是麦轮的弱项**（我们 10-08 实测过 TT 马达爬不上去）。
> 所以 1 号车的实际路线要改成：**先在地面把 a8/h1/c4/f5 收完 → 回不到 h5 就别硬爬，
> 直接从 a4 方向经桥进入中央系统**（a4 也是高台、有 a5/a6 坡道）。
> **这一条需要现场跑一次确认哪条路上得去**，标记为【待实测】。

**当前状态**：
- ✅ 分工结论已修正：**两车 27 : 16，最大单台占比 63%**，不再是 80% 的单点依赖；
- ✅ 总分预期从 30 提到 43；
- ⚠ **1 号车的上下高台路线未实测**（是本文档最大的待验证项）；
- ⚠ 洞穴黄块的探取方式（是"铲推"还是"挑杆勾"）需实物确认；
- 【待实测】中央高台面上的白块**到底有几个**（目前按 4 个估，需现场数）。
