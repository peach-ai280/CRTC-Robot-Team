## 一、底盘全向运动与麦轮防滑

### 功能描述

用四个麦克纳姆轮实现全向移动：前后、左右平移、原地自转。硬指标有两条：

- 五种动作都得能做出来；
- **横移和斜走的时候，车不能自己偏航** —— 方向一偏，后面的对位、收集全白做。

### 开发历程

**第一步：先在纸上推运动学，不着急写代码。**

麦轮的辊子是斜 45° 装的，四个轮的转速组合能合成任意方向的速度。我们按 X 型布局（左前、右前、左后、右后四个轮各自斜向不同）手推了逆解公式：给一组(vx 前进, vy 横移, wz 自转)，算出四个轮各自该转多快。

推完才发现，光有公式不够 —— 真正的麻烦在"算出来的值超过 100% 怎么办"。

**第二步：踩到最经典的一个坑——横移时车自己转圈。**

最初的写法是给四个轮**各自**限幅：谁的转速超过 1，就把它截断到 1。看着很合理，实际是错的。

原因是：当横移速度给到比较大的时候，四个轮解算出来的值大小不一，有的轮超了 1 被截掉，有的没超原样保留 —— **四个轮之间的相对比例被破坏了**，合成出来的速度方向就歪了。表现出来就是"推的是正左，车却斜着走"，转弯时车还会自己画弧。

**第三步：解法——整体等比归一化，不逐轮截断。**

改成：先扫一遍四个轮，找出绝对值最大的那个；如果它超过 1，就让**四个轮同时**除以这个最大值。

这样比例永远不变，只是整体"降速"。方向严格保住，代价是速度慢一点 —— 这个交换完全值得。

> 这是我们这个周期**最重要的一次改动**。代码在 `mecanum.c` 的 `chassis_normalize()`，一共 10 行，但它是"车能走直"和"车走不直"的分界线。

**第四步：防滑四件套。**

麦轮的辊子是塑料的、接地面积又小，比普通橡胶轮更容易打滑，尤其起步和急转的时候。我们叠了四层：

| 措施 | 解决什么 | 实现在哪 |
|---|---|---|
| 加速度斜坡（加、减速分开设） | 起步别一脚踩到底，避免轮子空转 | `chassis_ramp()` |
| 死区（油门小于 0.18 当 0） | 摇杆回中不准，导致车"自己慢慢爬" | `stick_map()` |
| 起步助力 kick | 越过死区的第一下给个短促大电流，克服静摩擦 | `motor.c` |
| 高速限自转 | 速度越高，允许的自转上限越低，防甩尾 | `chassis_limit_yaw()` |

**为什么不做编码器闭环。** 编码器要另外买、要装、要标定，我们的时间不够。开环 + 把参数调好，对"收集方块"这个精度要求是够的。**代码里留了接口**（`USE_ENCODER` 宏），以后想加随时能加。

**核心代码就四个文件**，都在仓库里可以点开看：

| 文件 | 作用 |
|---|---|
| `firmware/Core/Src/mecanum.c` | 底盘四步管线 + 麦轮逆解 |
| `firmware/Core/Src/motor.c` | 单轮输出：死区 → 起步助力 → 电压补偿 |
| `firmware/Core/Inc/config.h` | 全部运动参数（速度、加速度、限幅、符号） |
| `firmware/Core/Src/test_motion.c` | 架空测试专用固件（串口发 w/a/s/d 直接控车） |

四步管线的调用顺序在 `Chassis_Update()` 里：斜坡 → 限自转 → 逆解 → 归一化 → 输出。

**当前状态**：⚠ **代码写完、离线仿真跑过，但一次都没上过真车。**
车轮、电机、底板还没到手，所有参数（速度增益、加速度、死区）都是按设计值填的初值，**必须靠实车标定**。
详细推导和调参对照表见 `docs/03_底盘运动与麦轮防滑.md`、`docs/调参指南.md`。

## 二、手柄遥控与运动控制输入

### 功能描述

用官方 PS2 无线手柄遥控机器人。除了"能控"，还有一条安全要求：**手柄一掉线，车必须立刻停下来**。

### 开发历程

**协议本身：SPI 模式 3。**

手柄通过 SPI 跟单片机通信。我们用的参数是 CPOL=High、CPHA=2Edge、分频 256（约 281kHz）。

分频为什么选这么大（也就是为什么这么慢）—— 便宜手柄在 500kHz 下会偶发丢帧。轮询一帧只要 0.26ms，在 5ms 的控制周期里只占 5%，**慢一点换来不丢帧，值得**。

**最折磨人的一个坑：DI / DO 接反，查了三个小时。**

现象是串口一直收不到任何按键数据，但接线按图接的。我们依次排除了：量接收器电压（正常）、换手柄（一样）、把 SPI 四种模式组合全试一遍（一样）。

最后用示波器看波形才发现——**MISO 上一一直是高电平**，说明我们的数据线接到了手柄的"数据输入"脚上。

根源是接收器的丝印是**站在手柄角度**命名的：

| 丝印 | 含义 | 该接 STM32 |
|---|---|---|
| DI | Data In（进手柄） | MOSI（PA7） |
| DO | Data Out（出手柄） | MISO（PA6） |

我们是站在单片机角度接的，正好反了。**教训写进代码注释了：PS2 连不上，先对调 PA6/PA7，十次有九次是这个。**

**进模拟量模式。**

手柄上电默认是数字模式，摇杆只有 0 和 255 两档，没法做速度控制。必须在初始化时进配置模式，把模拟量打开。注意**配置命令之间要有延时**——我们第一版没加延时，命令全被吞了，现象是"一直停在数字模式"。

**摇杆到速度的映射，做了两件事：**

- **死区**：摇杆回中不准（中位左右各偏几个数），小于死区的一律当 0，否则车会自己爬；
- **expo 曲线**：中间段更细腻、满舵不变。这样低速对位的时候好控，又不损失极速。

**掉线保护（这条是安全底线）。**

掉线时不能只是"不再更新指令" —— 那样车里会**保留最后一次的速度一直跑下去**，直到撞墙。必须显式清零：

```c
if (!PS2_Poll()) {
    lost_cnt++;
    if (lost_cnt > 25) {        /* 约 125ms */
        connected = 0;
        btn = 0;
        lx = ly = rx = ry = 0;  /* 关键：清掉残留摇杆量 */
    }
}
```

**没有串口怎么看状态。** 板载那颗 LED 顺手写了套状态机，不接串口也能判断故障在哪：

| LED 表现 | 含义 |
|---|---|
| 常亮 | 通了（模拟模式） |
| 每秒闪 2 下 | PA6 / PA7 接反了 |
| 每秒闪 1 下 | 对面没回应（接收器没插 / 手柄没开机） |
| 每秒闪 2 下（双闪） | 数字模式，需要断电重插 |
| 全灭 | 程序没跑起来 |

**当前状态**：⚠ **这是目前唯一在推进的一环。**
SWD 烧录链已经实测打通，正在接那 6 根线做桌面测试，**还没跑到"摇杆能控车"这一步**。
接线表、LED 判读、协议细节见 `docs/05_PS2手柄与遥控器.md`。

## 三、桌面调试与第一次实机联通

### 功能描述

搭一套能稳定"改代码 → 编译 → 烧进板子 → 看结果"的环境。这块不直接产出功能，但**它是上面两条能推进的前提**。

### 开发历程

**不用图形界面，全部脚本化。**

本机装了 STM32CubeIDE 2.2.0（它自带 ARM 编译器和烧录器），但我们**不进它的图形界面点来点去**，而是自己写了两个脚本：

- `tools/build.py` —— 一条命令编译出固件（本机没装 make，所以自己写构建脚本）；
- `tools/flash.py` —— 一条命令烧录，自动找到 CubeIDE 自带的烧录器。

好处是：改一行参数,敲一条命令就出固件，不用等 IDE 转圈。

**自制 HAL 兼容层。**

标准做法是用 ST 官方的 HAL 库 + CMSIS，但我们这套环境拿不到。于是我们**直接操作寄存器**，自己实现了业务代码用到的 20 来个 HAL 函数，**函数名和官方一模一样** —— 这样业务代码一个字不用改，将来拿到官方库也能一键切回去。用到了哪些开源东西，见 `docs/开源项目说明.md`。

**离线验证：在电脑上跑真实固件。**

我们用 ARM 模拟器在电脑上模拟一颗 Cortex-M3，直接把编译出来的**真实固件机器码**跑起来，看电机输出对不对。这样改一个参数不用每次都烧板子试。

**实测结果（2026-10-08）：**

```
ST-LINK SN  : E1007200D0D2139393740544
Voltage     : 3.21V
Device ID   : 0x410
Device name : STM32F101/F102/F103 Medium-density
NVM size    : 128 KBytes
[OK] 芯片连上了
```

**"电脑 → ST-LINK → SWD → 芯片"整条路是通的。** `3.21V` 那行说明板子确实在从 ST-LINK 取电，芯片被正常枚举。

**当前状态**：✅ 环境与烧录链已实测打通；⏳ 架空测试固件（`test_motion.c`）已就绪，等电机到手即可上电验证。

## 四、物资采购与成本

### 功能描述

这部分是我负责的。要做三件事：**把官方给的物资清点清楚**、**算出还缺什么**、**该买的买齐**，同时不违规、不浪费。

### 开发历程

**第一步：先把官方物资表逐条核一遍，知道"不用买什么"。**

手册附录的物资表一共 18 项、两台车合计 ¥353.48（每车 ¥176.74）。逐条看完有两个直接结论：

- 底板是**一体带马达孔**的金属折弯板 → **不用打印电机座**；
- 麦轮套装里**带 TT 马达联轴器** → **不用打印轮毂**。

这一条很重要：**说明在机械臂定稿之前，我一个 3D 打印件都不需要，切片和耗材一根都不用动。**

**第二步：算缺口，查出三个官方没覆盖的地方。**

| 缺口 | 情况 | 我们的做法 |
|---|---|---|
| **USB 转串口模块** | 官方 18 项里**完全没有** | 自购 CH340 模块（¥6~8）。看不到摇杆值、占空比、电池电压就没法标定 |
| **SG90 舵机数量** | 官方每车只给 2 个，而"舵机运动（多项）"要求**同一台车 3 个同时动** | 走"两台车的舵机集中到一台车上拍"，不额外花钱 |
| **舵机 5V 供电** | 官方每车只给 1 个降压模块，它还要同时喂单片机 | 补 1 个降压模块给舵机单独一路（**分路不算违规**，规则管的是电池那一层）+ 0.1µF 瓷片电容 |

**第三步：按"现在就要用"分层买，不一次性囤齐。**

因为机械臂还没定稿，我把清单分了三档：

| 档 | 内容 | 什么时候买 |
|---|---|---|
| **桌面测试** | USB 转串口、电烙铁套装、热缩管、加长杜邦线 | **现在**（桌测用） |
| **底盘装配** | M3 螺丝螺母（含 ×8）、尼龙扎带 2.5mm | **等电机到手**（焊马达线、拧到底板） |
| **机构装配** | Φ3 光轴、M2.5 自攻、拉簧、PLA 胶、平垫圈 | **等机械臂定稿**（现在一样不买） |

**明确不买的（都写清理由）：**

- **无线继电器** —— 手册原文"**通过中期测评的队伍需要购买**"，中期这一步不买，这 ¥27.6 先不花；
- **热熔胶枪** —— 手册结构规范第 1 条明写"尽量避免采用热熔胶"；
- **电机座 / 轮毂 / 联轴器** —— 官方物资已经给了。

**当前状态**：⚠ 采购单已出、分档已定，**USB 转串口和电烙铁还没下单**。
完整清单见 `D:\WorkBuddy\CRTC交付\` 下的 `最终版采购清单.md`、`连接件与固定件采购单.md`、`淘宝搜索词_直接复制.md`。
