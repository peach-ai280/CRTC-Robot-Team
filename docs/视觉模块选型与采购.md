# 视觉模块选型与采购

> 结论先说：**买 K210（MaixPy 固件）**。别买 OpenMV，别买 ESP32-CAM。
> 但**优先级排在基础功能之后**——你预算已经超了，见最后一节。

---

## 一、三个候选的横向对比

| | **K210** | OpenMV | ESP32-CAM / ESP32-S3 |
|---|---|---|---|
| 主控 | 双核 RISC-V 400MHz + KPU | STM32H7 | Xtensa |
| 算力 | ~1 TOPS | 无专用加速 | 弱（S3 稍强） |
| 摄像头 | 2MP OV2640 | 5MP | 2MP |
| **自带屏幕** | **有（2.0~2.4 寸）** | 无 | 无 |
| 编程 | MaixPy（MicroPython） | MicroPython | MicroPython / C |
| 与 STM32 通信 | **串口，直接输出坐标** | 串口 | 串口 / WiFi |
| 国内价格 | **¥120 ~ 200** | ¥300 ~ 500 | ¥40 ~ 90 |
| 色块识别 | 很好 | 很好 | 一般 |

### 为什么是 K210

1. **自带屏幕——这一条对新手是决定性的。**
   你调颜色阈值的时候，能直接在模块屏幕上看到"它认为的白色方块在哪"。
   没有屏幕的模块（OpenMV / ESP32-CAM），你只能靠串口打印数字去猜，
   调一次阈值要半小时，调十次就是半天。**新手最大的成本是反馈慢。**

2. **算力有富余。** 现在只做色块识别，K210 杀鸡用牛刀。
   等你想加"识别黄色核心 vs 白色单元"（我们正好要区分这两种），
   它的 LAB 阈值 + 面积筛选很轻松，不至于跑到一半卡帧。

3. **串口协议简单。** 就发坐标，STM32 那边 `vision.c` 已经写好了解析器。

### 为什么不选另外两个

- **OpenMV**：功能一样，贵一倍多，还没屏幕。学生比赛没必要。
- **ESP32-CAM**：便宜，但识别能力和稳定性都差一档，
  而且它主打 WiFi 图传——我们要的是"本地出结果"，图传对我们没用。
  省下的钱不值得赌在赛场上。

## 二、具体买什么

淘宝 / 拼多多搜关键词：**`K210 开发板 MaixPy`** 或 **`K210 视觉模块 串口`**

认这三条，满足就能买：
1. **芯片是 K210**（不是 K230，K230 生态还差点意思）
2. **带 2.0 或 2.4 寸屏**
3. **引出 UART 串口排针**（VCC / GND / TX / RX 四根）

常见可选：
- **Sipeed Maix Bit / MaixDock**（最主流，资料最多）
- **亚博 Yahboom K210 模块**（带支架，好固定）
- **正点原子 / 逐飞 K210 模块**（竞赛圈用得多，例程偏竞赛向）

> 价格我没法给你准确数字，¥120~200 是常见区间，
> 买的时候注意：**要带屏的那个版本**，裸板便宜但难调。

**顺手买**：
- 一根 4P 杜邦线（母对母）
- 几颗 M3 螺丝（固定模块到车上，我们机械件里留了视觉支架孔位）
- 一卷黑色电工胶带（遮住模块上的 RGB 灯，它会在场地上干扰颜色识别）

## 三、接线：只要 4 根线

```
K210 模块            STM32F103C8T6
  VCC   ────────────  5V        ⚠ 必须接 5V，不能接 3.3V
  GND   ────────────  GND
  TX    ────────────  PA10 (USART1_RX)
  RX    ────────────  PA9  (USART1_TX)
```

**注意两点**：

1. **TX/RX 要交叉。** 模块的 TX 接单片机的 RX，反了就完全收不到数据。
   这是最常犯的错，现象是"串口一个字节都没有"。
2. **电源要单独给。** K210 峰值电流不小（带屏能到 300mA+），
   **别从 STM32 开发板的 3.3V 取电**，会拉塌电压导致单片机反复复位。
   从 5V 降压那一路取（和舵机分开，别共用）。

## 四、代码已经写好了，你不用再写

| 文件 | 作用 |
|---|---|
| `vision/k210_find_cube.py` | 烧进 K210 的 MaixPy 脚本：找白色/黄色色块，按协议发坐标 |
| `firmware/Core/Src/vision.c` | STM32 端：解析 14 字节定长帧，`AA 55 cls x y w h area chk` |
| `firmware/Core/Inc/config.h` 第 6 节 | `USE_VISION` 开关 + P 控制参数 |

### 帧格式（两边必须一致，改一个就要改另一个）

```
字节:  0     1     2      3    4    5    6    7    8-11   12-13  14
      AA    55   cls    x_h  x_l  y_h  y_l  ...   area    ...    chk
```
`chk` 是前 13 个字节的异或。校验不通过就丢弃——
这一条很重要，串口在电机旁边会被干扰，没校验会收到一堆垃圾坐标。

### 现在就能测（不用买硬件）

```
python tools/build.py vision
python tools/flash.py vision
```
串口发 `t` / `y` / `n`，单片机会自己造一帧数据喂给解析器，
验证解析和 P 控制逻辑。**这个今天就能做，不用等模块到货。**

## 五、买了之后的调试流程（五步）

1. **先不接 STM32。** 模块插电脑，用 MaixPy IDE 跑 `k210_find_cube.py`，
   屏幕上应该能看到识别框。看不到就是阈值不对。

2. **调颜色阈值。** 脚本里有 `CALIB_MODE`，打开后屏幕上会打出
   当前画面中心点的 LAB 值。把方块放在镜头前，读数，填进阈值数组。
   **白色单元和黄色核心要分两组阈值**，这就是 `cls` 字段的作用（0=白 1=黄）。

3. **关掉自动增益和自动白平衡。** 脚本里已经关了。
   别手贱打开——场地灯光一变，开着自动增益的阈值就全废了。

4. **接上 STM32，看串口。** 烧 `vision` 固件，串口会打印
   `vis cls=0 (x,y) area=xxxx`。手拿方块在镜头前晃，数字应该在动。

5. **最后才测 P 控制。** 烧 `full` 固件，按 L2 触发视觉宏，
   看车会不会朝方块转过去。
   - 转反了 → `VISION_TURN_KP` 加负号
   - 转过头来回摆 → `VISION_TURN_KP` 调小
   - 顶太近了才夹 → `VISION_NEAR_AREA` 调小

## 六、⚠ 关于预算，有句话必须说

你现在的成本已经 **≈ ¥415**，超过了新生组 **¥400** 的报销上限。
K210 模块还要再加 ¥120~200。

**我的建议是：先别买。**

理由：
- 我们的**主方案是机械对中**（V 型喇叭口 + 双微动开关），不依赖视觉，
  不受光照影响，成本已经算在现有的 ¥415 里了。
- 视觉在我们的方案里是**进阶加分项**，不是必需品。
- 一局只有 5 分钟，视觉带来的收益未必抵得上你调它花的时间。

**什么时候买？** 等你把半自动跑稳、机械对中成功率上去了、手里还有闲钱，
再买来锦上添花。那个时候你也有经验了，半天就能调通。

如果你现在就想下单——可以，代码都准备好了，买回来接 4 根线就能用。
只是别让它拖慢主线进度。
