# PS2 手柄遥控与通信

## 功能描述

用组委会提供的 PS2 无线手柄（可对频锁定款）控制机器人，
并且**手柄掉线时车必须停下来** —— 这是安全要求，不是可选项。

代码：`firmware/Core/Src/ps2.c`，协议参数见 `config.h` 第 5 节。

---

### 2026-09-20 · SPI 配置：为什么是 CPOL=High / CPHA=2Edge

PS2 手柄的 SPI 时序是**空闲时钟为高、在第二个边沿采样**（SPI 模式 3）。
CubeMX 里对应：

```
SPI1: Full-Duplex Master, Software NSS
      CPOL = High
      CPHA = 2 Edge
      MSB First, 8 bits
      Baud Prescaler = 256   (72MHz / 256 ≈ 281kHz)
```

**波特率为什么选 256 而不是更快**：PS2 协议本身上限大概 500kHz，
但便宜手柄/接收器在 500kHz 下会偶发丢帧。281kHz 稳得多，
而我们一帧轮询只要 9 字节 × 8 bit / 281kHz ≈ 0.26ms，
5ms 控制周期里占 5%，完全够用。**宁可慢，不要偶发掉线。**

### 2026-09-27 · DI / DO 接反：调了三个小时的问题

**现象**：串口一直没有任何按键数据，`mode` 一直是 0。

**排查过程**（按顺序）：

1. 量接收器 VCC —— 3.3V 正常
2. 换了一个手柄 —— 还是不行
3. 怀疑 SPI 时序 —— 把 CPOL/CPHA 四种组合都试了一遍 —— 还是不行
4. 用示波器看 SCK 和 MISO —— **SCK 有波形，MISO 一直高**

第 4 步暴露了真相：**我们的 MISO 接到了手柄的 DI（数据输入）脚上**。

PS2 接收器的丝印是站在**手柄**的角度命名的：

| 模块丝印 | 含义 | 接 STM32 的 |
|---|---|---|
| DI | Data **In**（进手柄） | MOSI（PA7） |
| DO | Data **Out**（出手柄） | MISO（PA6） |

我们是站在 MCU 角度接的，正好反了。

**记下来的排查口诀**（写进了代码注释）：
> PS2 一直连不上，先把 PA6 / PA7 对调。**90% 的 PS2 调不通都是这两根线反了。**

### 2026-09-27 · 进模拟量模式：不然摇杆只有 0 和 255

手柄上电默认是**数字模式**，摇杆只回 0x00 / 0xFF 两档，没法做速度控制。

必须在初始化时进配置模式打开模拟量：

```c
enter_cfg :  01 43 00 01 00
set_mode  :  01 44 00 01 03 00 00 00 00    // 0x01 = 开模拟量
set_rumble:  01 4D 00 00 01 FF FF FF FF    // 关震动（省电 + 防接插件松）
exit_cfg  :  01 43 00 00 5A 5A 5A 5A 5A
```

**成功的标志**：手柄上的 MODE 灯**红灯常亮**（数字模式是不亮或另一种状态）。
串口打印的 `mode` 字节应该是 `0x73`（模拟绿灯）或 `0x79`（模拟红灯），
不应该是 `0x41`。

**注意**：进配置模式之前要先短轮询 3 次让手柄"醒"过来，
每条配置命令之间要有延时。我们第一版因为没加延时，配置命令全被吞了。

### 2026-09-27 · 字节间延时：便宜手柄必须要

在 `ps2_xfer()` 里每发一个字节后加了约 15μs 的延时（用 `__NOP()` 循环实现，
72MHz 下大约 9 个循环 = 1μs）。不加的话接收器跟不上，表现为偶发掉帧。

不能用 `HAL_Delay(1)`：一帧 9 个字节就是 9ms，而我们的控制周期才 5ms，会直接卡死调度。

### 2026-09-28 · 掉线保护：车绝不能"保持上一个指令继续跑"

这是安全设计，**不是可选优化**：

```c
if (!PS2_Poll()) {
    lost_cnt++;
    if (lost_cnt > PS2_LOST_THRESHOLD) {   // 25 次 ≈ 125ms
        connected = 0;
        btn = 0;
        lx = ly = rx = ry = 0;             // 关键：清掉残留摇杆量
    }
}
```

在 `app.c` 里：

```c
if (!ps2.connected) { vx = vy = wz = 0.0f; }
```

**为什么必须显式清零**：如果只做"不再更新指令"，
`g_cur` 里会保留掉线前最后一次的速度，车会**一直以那个速度跑下去**，
直到撞墙或撞人。这在 2400×2400 的对抗场里是实打实的危险。

LED 指示也接上了：手柄失联时 LED 从 1Hz 慢闪变成**常亮**，
操作手在场上不用看串口就知道发生了什么。

### 2026-09-28 · 摇杆映射：死区 + expo 曲线

| 问题 | 解法 |
|---|---|
| 摇杆回中不一定是精确的 128 | `PS2_STICK_DEADZONE = 12`，中间 ±12 当 0 |
| 去掉死区后低速有跳变 | 去掉死区后重新归一化到 0~1，再套 expo |
| 低速时太灵敏，难做精细对位 | `PS2_STICK_EXPO = 1.4`，指数曲线让中段更细腻 |

```c
a = (|x| - dz) / (1 - dz);     // 去掉死区并重新归一化
return sign(x) * powf(a, EXPO); // expo > 1 => 低速更细腻
```

### 2026-10-07 · 按键映射定稿

| 键 | 功能 | 为什么放这里 |
|---|---|---|
| 左摇杆 | 前后 + 左右平移 | 麦轮全向，直觉 |
| 右摇杆 X | 自转 | 和左摇杆分开，避免误触 |
| ○ | 宏1 地面自动收集 | 最常用的动作，放在最顺手的键 |
| △ | 宏2 挑物资架黄块 | |
| □ | 宏3 洞窟探杆 | |
| × | 宏4 一键贴边 | |
| L2 | 宏5 视觉对位（进阶） | 没开视觉时 L2 复用为前铲微调 |
| L1 | 全部机构收起（检录姿态） | 每局开始前必须按一次 |
| R1 | 前铲放下/抬起切换 | |
| SELECT | 手动 / 半自动切换 | |
| START | 急停（再按解除） | |
| ↑↓ / ←→ | 大臂 / 夹爪 ±2°（标定用） | **在线标定，见下** |

**在线标定是这套按键设计里最实用的一条**：
用方向键微调舵机角度，串口会实时打印当前角度，
调到满意的角度后直接把数字抄进 `config.h`。

比起"改宏 → 编译 → 下载 → 看效果"的循环（每次至少 1 分钟），
在线标定把一次迭代压到几秒钟。**舵机角度这种必须靠眼睛调的参数，
没有这个工具几乎没法调。**

### 2026-10-08 · 宏运行期间的人工接管

**设计**：宏运行期间，只要操作手动了摇杆（三轴绝对值之和 > 0.35），
立刻中止宏、交还控制权。

```c
if (Auto_Running()) {
    float mv = |stick(ly)| + |stick(lx)| + |stick(rx)|;
    if (mv > 0.35f) { Auto_Abort(); }
}
```

理由很简单：宏是**基于时间参数的盲走**，一旦现场情况和我们标定时不一样
（方块被对手推走了、地面脏了打滑了），继续跑下去只会把车顶在墙上。
让操作手随时能接管，是这个宏敢上场的唯一原因。

## 本板块参数

| 宏 | 值 | 备注 |
|---|---|---|
| `PS2_STICK_DEADZONE` | 12 | 手柄个体差异大，可到 20 |
| `PS2_LOST_THRESHOLD` | 25 | ≈ 125ms，再长就有安全风险 |
| `PS2_STICK_EXPO` | 1.4 | 1.0 = 线性 |
| SPI 预分频 | 256 | ≈ 281kHz |
| 字节间延时 | 15μs | 便宜手柄必加 |
