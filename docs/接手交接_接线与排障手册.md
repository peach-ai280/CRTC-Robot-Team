# 整车接线指南 + 两个待解决问题排查手册（接手版）

> 写给接手同学：这份文档的目标是让你**不靠口口相传**，独立完成两件事——
> ① 查清整车的每一根线；② 解决两个已定位的问题（PS2 配对成功但不传信号、ST-Link 拔掉就没电）。
>
> 安全前提写在最前面，务必先读再动手。

## 0. 安全前提（动手前必读，不是客套话）

1. **先断电再动线。** 拔电池、拔 USB 之后再插拔任何杜邦线。带电插拔杜邦线是烧 STM32 的第一大原因——插歪一位（5V 怼到 3.3V 脚）当场就废。
2. **第一次上电先架空。** 车轮离地，别让车一上电就窜出去。电机堵转、急停误触发都是常见伤车方式。
3. **万用表是你唯一的裁判。** 判断「这根线通不通、这个点有没有电」，用万用表蜂鸣档和电压档，不要用「看着像接对了」。
4. **克隆版 ST-LINK 的两个坑先记牢**（后面会反复用到）：
   - 我们那块 ST-LINK 是**克隆版 V2**，CubeProgrammer 握手会报 `DEV_CONNECT_ERR`，**不是线接错了**。烧录一律走 OpenOCD，脚本已经在仓库里备好。
   - SWD 四根线的顺序**不能整排直插**：Blue Pill 板顶是 `3V3 / SWIO / SWCLK / GND`，ST-LINK 右列是 `SWCLK / SWDIO / GND / 3.3V`，顺序相反。必须四根独立线按丝印对插。

## 1. 全车电源：三条主干 + 一个单独点

整辆车只有 **一个电源来源**（2×18650 串联 = 7.4V），所有分支都在电池之后分。记三条主干和一个单独点，接线就不乱：

| 主干 | 颜色 | 谁并进来 |
|---|---|---|
| **COM（单独）** | — | 电池正极，**只进继电器 COM，一根线，不跟任何负载并** |
| **7.4V 主干** | 红 | 继电器 `NO` + 降压模块 `IN+` + 电机驱动 `VM` |
| **5V 主干** | 橙 | 降压模块 `OUT+` + 继电器 `+V` + 舵机 `VCC` + STM32 的 5V 脚 |
| **地主干** | 黑 | 电池负 + 降压 `IN−`/`OUT−` + 继电器 `-V` + 电机 GND + 舵机 GND + PS2 GND + STM32 GND |

**电流走向一句话**：
```
电池 7.4V 正 → 继电器 COM →（吸合后）NO → 7.4V 主干
                                          ├→ 降压模块 IN+ ── OUT+ → 5V 主干
                                          └→ 电机驱动 VM
电池 7.4V 负 ──────────────────────────────→ 地主干（所有元件共地）
```

**施工顺序**：先接地 → 再 7.4V → 再 5V → 最后信号线；电池放最后一步。每接完一坨，用万用表量「地与 7.4V」是否短路（蜂鸣档，不该响），确认不短路再往下走。

### 1.1 无线继电器（5 端子款，别跟 4 端子款搞混）

实物是 SONGLE SRD-05VDC-SL-C 无线遥控型，绿色端子从左到右：

```
-V   +V   NO   COM   NC
```

| 端子 | 接哪 | 说明 |
|---|---|---|
| `COM` | 电池正 7.4V | 公共端，只进电池正 |
| `NO` | 7.4V 主干 | 常开触点，遥控吸合后才通电 |
| `+V` | 5V 主干 | 线圈供电正 |
| `-V` | 地主干 | 线圈供电负 |
| `NC` | 悬空 | 常闭，不接 |

**两个必踩的坑**（都真实踩过）：

- **线圈供电别接错位置**：`+V/-V` 要从 **5V 主干**取电，绝不能接在 `NO` 后面的 7.4V 上。否则一按断电，继电器自己也断电，再也合不上，车永久断电。
- **点动式 vs 自锁式**：我们拿到的是**点动式**（按住通电、松手断电），不是自锁式（按一下切换）。这个和检录「遥控切断总电」的要求有冲突，是历史遗留问题，接手时先确认车上这块到底哪种。

### 1.2 降压模块（非隔离 DC-DC）

四个焊盘：`IN+ IN− OUT+ OUT−`。

| 焊盘 | 接哪 |
|---|---|
| `IN+` | 继电器 `NO`（= 7.4V 主干），**不是 COM** |
| `IN−` | 地主干 |
| `OUT+` | 5V 主干 |
| `OUT−` | 地主干 |

要点：`IN−` 和 `OUT−` 内部共地，**不用自己再焊一起**；`IN+` 反接直接烧；`IN+` 接 COM 的后果是降压在开关之前，遥控断电后单片机还亮着，检录不合格。

## 2. 各元件信号线（和电源线分开记）

信号线是**另一组**，别和电源混。

| 元件 | 信号线 | 电源/地 |
|---|---|---|
| **PS2 接收器** | CLK→PA5、CMD→PA7、DAT→PA6、ATT→PB0 | VCC→3.3V，GND→地 |
| **舵机（挑杆/备用）** | 信号→PA3 | VCC→5V，GND→地 |
| **电机驱动 DRV8833** | IN1~IN4→PB6~PB9（PWM），方向脚→PB12~15 | VM→7.4V，GND→地 |
| **DRV8833 nSLEEP** | 拉高（接 5V） | 悬空 = 电机完全不转 |

### 2.1 PS2 接收器 ↔ Blue Pill（一对一，重点）

PS2 接收器丝印是**站在手柄角度**命名的，DI/DO 特别容易接反：

| 接收器丝印 | 含义 | 接 Blue Pill |
|---|---|---|
| `DAT` / `DO` | Data Out（接收器说话） | **PA6**（MISO） |
| `CMD` / `DI` | Data In（单片机说话） | **PA7**（MOSI） |
| `CLK` / `SCK` | 时钟 | **PA5** |
| `ATT` / `CS` | 片选（拉低选中） | **PB0** |
| `VDD` | 电源 | **3.3V**（别接 5V） |
| `GND` | 地 | **GND** |

**90% 的「PS2 连不上」都是 PA6/PA7 接反了**。上面表格是对的，照抄接线即可。PA5/PA6/PA7/PB0 在 Blue Pill 左排是连续 4 针，很好插。

## 3. 待解决问题一：PS2 配对成功，但不传信号

### 3.1 现象与已知背景

手柄和接收器**已经对上频**（接收器/手柄的灯常亮，不是慢闪），但 STM32 收不到有效帧——表现为推摇杆车不动、`g_ps2` 的 `valid_frames` 一直是 0。

**历史背景（重要，别重复踩坑）**：之前排查到「四个信号脚被钉死」——A5/B0 被钉在 0V，A6/A7 被钉在 3.3V，24 种接法全试都不回话。但你现在说「配对成功了」，说明状态可能有变化（可能换过板、可能重新接过线）。所以**重新按下面步骤测一遍，不要默认是上次的结论**。

### 3.2 先分清「配对」和「通信」是两段独立的链路

这是最关键的一点，很多人卡在这：

```
手柄 ──(2.4G 无线)──▶ 接收器 ──(SPI 有线)──▶ STM32
      配对成功这一段           通信这一段
```

- **绿灯/红灯常亮 = 配对成功**，只说明「手柄 ⇢ 接收器」这段 2.4G 无线是通的。
- **STM32 能不能收到 = 通信**，取决于「接收器 ⇢ STM32」这 6 根线接对没有、接收器有没有电。

**两段互不相干**。配对成功**完全不能证明**有线通信那段是好的。你现在的问题，几乎可以肯定出在「接收器 ⇢ STM32」这一段。

### 3.3 排查步骤（按顺序，用万用表）

**第 1 步：确认接收器真的通电。**

- 万用表电压档，红笔点接收器 `VDD`、黑笔点 `GND`。
- 应该读到 **3.2~3.3V**（如果接收器是 3.3V 款）。
- 读 0V → 电源没接上（继电器没开 / 接错在 NO 上被切断了 / 线断了）。
- 读 3.3V 但模块灯不亮 → 换 5V 试（有些便宜模块 3.3V 下逻辑走不动，只亮灯或连灯都不亮）。

**第 2 步：核对 6 根线一一对应。**

对照上面 2.1 的表格，重点检查 `DAT→PA6`、`CMD→PA7` 这两根有没有反。这是 90% 问题的根源。

**第 3 步：跑硬件诊断脚本（仓库已备好）。**

烧车一固件并验证：

```bash
cd C:/Users/hp/WorkBuddy/CRTC
python tools/flash.py v2s          # 烧车一固件
python tools/verify_v2.py          # 读 g_ps2 的 valid_frames / fail_count
```

看三个数：
- `valid_frames > 0` → 通了，问题在别处（去查舵机/电机那路）。
- `last_length == 0` → 一帧没收到，回到第 1、2 步查 6 根线。
- 9 字节全 `FF` → 接收器在线但不应答（见第 4 步）。

**第 4 步：做 24 种接法穷举扫描（定位「脚被钉死」）。**

```bash
python tools/ps2_scan.py --restore v2s
```

这个脚本会把 A5/A7/A6/B0 四个脚在 CLK/CMD/CS/DAT 四个角色间全排列（24 种），逐个试，然后**自动反推每个脚的真实电平**。看结论：

- 若说「某脚被钉死在 0V / 3.3V」→ 这根线被短到电源/地，或芯片引脚坏了。**先拔掉接收器 4 根信号线重跑一次**：
  - 拔掉后不钉死了 → 是线的问题，一根一根插回去，插一根量一次。
  - 拔掉后还钉死 → 芯片引脚坏了，换备用 Blue Pill。
- 若 24 种全不回话、且没有钉死 → 回到第 1 步查供电和 6 根线。

**第 5 步：排除「代码把接收器锁进配置模式」。**

这个 bug 已经在 `firmware_v2` 修掉了（上电第一帧无条件发 `leave` 退出配置模式，之后只在「真读到数字模式」时才协商）。但如果你烧的是**旧固件**（`firmware/` 目录下的老版），仍可能锁死。

判断法：**真拔电池断电、再上电**（只按 ST-LINK 复位不算，因为接收器一直带电不跟着复位）。断电能恢复 = 是被锁；断电能恢复不了 = 硬件问题。

## 4. 待解决问题二：ST-Link 拔掉就没电（无法脱机）

### 4.1 根因（已定位，不是接线错）

工程日志里明确记录过：**车载 5V 降压模块「用坏了两个、剩下一个找不到」**，所以 STM32 目前是**直接从 ST-LINK（USB）取电**。拔掉 ST-LINK，供电就断了，车自然没电。

**这不是接错线，是「5V 降压模块」这个件缺料/损坏。** 解决它的唯一正确路径，是让 STM32 的 5V 脚**接到车上自己的 5V 主干**（降压模块 OUT+），而不是靠 ST-LINK。

### 4.2 供电链路应该长什么样

Blue Pill 板载一颗 AMS1117-3.3 稳压器，它把 5V 转成 3.3V 给芯片。所以：

```
电池 7.4V → 继电器 NO → 降压模块 IN+ → 降压模块 OUT+（5V）
                                      └→ Blue Pill 的「5V」脚 → 板载 AMS1117 → 3.3V 给芯片
```

**关键：Blue Pill 的「5V」脚必须接到车载降压模块的 OUT+（5V 主干）。** 如果这个 5V 脚现在是空的、或者只接在 ST-LINK 上，那拔掉 ST-LINK 必然断电。

### 4.3 排查与修复步骤

**第 1 步：确认降压模块现在到底还在不在、好不好用。**

- 车上有没有降压模块？之前记录是「用坏两个、剩一个找不到」。
- 如果有一个，用万用表量：输入端（IN+ / IN−）接 7.4V，量输出端（OUT+ / OUT−）是不是 **5.0V ± 0.2V**。
- 如果量不到 5V → 降压模块坏了，换一个（这是耗材，必买，单价几块钱）。

**第 2 步：确认 Blue Pill 的 5V 脚接到哪了。**

- 顺着 Blue Pill 的「5V」脚这根线，看它另一头接在哪。
- 正确：接到降压模块 OUT+（= 5V 主干）。
- 错误：悬空、或只连在 ST-LINK 上。

**第 3 步：把 5V 脚正确接上，然后做脱机测试。**

1. 接好：降压 OUT+ → Blue Pill 5V 脚。
2. 断开 ST-LINK（拔掉 USB）。
3. 打开电池供电（按继电器遥控，让 NO 通电）。
4. 看板载 LED（PC13）有没有按程序亮/闪。亮 = 供电通了，脱机成功。

**第 4 步：脱机成功后再做一次完整验证。**

```bash
python tools/verify_v2.py
```

确认 `valid_frames > 0`、无复位，才算「脱机也能正常跑」。

### 4.4 为什么不能「7.4V 直接进 3.3V 脚」

Blue Pill 的 3.3V 脚是**输出**（AMS1117 的输出），不是输入。7.4V 直接怼上去会烧掉 AMS1117 和芯片。7.4V 只能从 5V 脚（经 AMS1117）进，或者从 3.3V 脚进的前提是**电压本身是 3.3V**（比如 ST-LINK 的 3.3V 输出）。所以脱机供电的正确入口是 **5V 脚，接 5V 主干**。

## 7. 上手顺序（建议照着走）

1. 先跑 `python tools/env_check.py`，确认 ST-LINK 和 OpenOCD 能握上手。
2. 花 10 分钟把第 1、2 节的三条主干 + 信号线对照实车走一遍，用万用表蜂鸣档逐根确认。
3. 解决**问题二（脱机供电）**——因为不解决它，你永远得拖着 USB 线，没法真跑。核心就是给 Blue Pill 的 5V 脚接上车载 5V。
4. 再解决**问题一（PS2 不传信号）**——按第 3 节顺序，从「接收器有没有电」开始。
5. 每解决一个，跑一次 `verify_v2.py` 留证据，并把结果写进 `docs/工程日志.md`。
