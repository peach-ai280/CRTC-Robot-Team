# 半自动与视觉

## 功能描述

让操作手**按一个键**就能完成"对中 → 夹紧 → 抬起 → 入仓"，
从而争取手册里的**半自动得分倍率**（能量单元 ×1.5、能量核心 ×1.25）。
视觉（K210）作为**进阶功能**独立评估，不进主链路 —— 视觉挂了车还能打。

代码：`auto_task.c`（宏状态机）、`sensor.c`（对中检测）、`vision.c` + `vision/k210_find_cube.py`。

---

### 2026-09-17 · 先说清楚：半自动不是强制项

我们逐条核对了手册 4.1 的基础功能清单，**没有**"必须完成半自动"这一条。
手册里关于自动/半自动的内容只有两处：

1. 定义（3.3.1）：全自动 = 无需操作手 + 经组委会审查确定；只满足一部分 = 半自动
2. 得分倍率（4.2）：全自动 能量单元 ×2 / 核心 ×1.5；半自动 ×1.5 / ×1.25

所以半自动是**加分手段**而不是及格线。我们仍然要做，因为 1.5 倍是白给的，
但要把它做成"**稳**的半自动"而不是"炫的半自动"。

### 2026-09-26 · 技术选型：机械对中 vs 视觉识别

| 方案 | 原理 | 优点 | 缺点 | 成本 |
|---|---|---|---|---|
| **机械对中（微动开关）** | V 型喇叭口两侧各一个摆杆，方块同时压到两者 = 已居中 | 不受光照影响、不需要调阈值、响应 < 30ms、新手半小时能调通 | 只能对正前方约 ±20° 的方块 | ¥5 |
| 视觉识别（K210/OpenMV） | 色块识别 → 串口发坐标 → P 控制转向对位 | 能主动搜索、距离远也能对 | 受光照影响大、阈值要现场抠、需要额外 UART + 供电、新手调试周期长 | ¥60~90 |

**决策：机械对中做主方案，视觉做进阶功能。**

理由：

1. 我们的核心诉求是"**稳定拿到半自动倍率**"，不是"炫技"。
   机械对中的失败模式是"没对准"（车停下来，操作手再试一次），
   视觉的失败模式是"对到了错误的目标"（车冲向错误方向，可能撞墙）。
2. 成本：视觉模块 60~90 元会让我们**超过 400 元的推荐成本线**。
3. 时间：中期考核前只有 3 周，视觉的阈值标定 + 串口联调 + 控制参数整定
   至少占用 1 周，会挤压底盘和机构的调试时间。

**但视觉代码我们照样写了**（`vision/` 目录 + `config.h` 的 `USE_VISION` 开关），
因为它是很好的**进阶功能**素材（最多 3 项、最高 +9 分），
而且中期考核后如果晋级，有预算再买也不迟。

### 2026-10-05 · 对中检测：两个微动开关 + 时间窗口

硬件：V 型喇叭口两侧各装一个 KW11 微动开关，带 45mm 长的摆杆
（`06_limit_lever.stl`），摆杆被方块压向内侧时开关闭合。

判定逻辑（`sensor.c`）：

```c
// 判定"已对中"：左右两个开关都被压过，且两次压下时刻相差 < 400ms
uint8_t Limit_Centered(uint32_t now) {
    if (!l_stable || !r_stable) return 0;
    if (now - l_hit_ms > LIMIT_BOTH_WINDOW_MS) return 0;
    if (now - r_hit_ms > LIMIT_BOTH_WINDOW_MS) return 0;
    int32_t diff = l_hit_ms - r_hit_ms;
    return (|diff| <= LIMIT_BOTH_WINDOW_MS) ? 1 : 0;
}
```

**为什么要"时间窗口"而不是"同时闭合"**：

方块进喇叭口时几乎不可能**精确同时**压到左右两个摆杆 ——
总会有一侧先被碰到。如果要求"同时闭合"，实际永远触发不了。
用 400ms 的窗口，允许先后差 400ms 以内都算对中，鲁棒性立刻上来。

**为什么还要"两个都闭合"**：
只压到一个说明方块是斜着进来的（撞在喇叭口一侧），这时候夹紧会夹空。

去抖 30ms（微动开关机械抖动典型值 5~20ms）。

### 2026-10-07 · 一键宏 v1

状态机（`auto_task.c`）：

```
step 0: Arm_Start(POSE_READY)        前铲放下、夹爪张开
step 1: 等机构到位（>2s 判失败）
step 2: 以 0.35 慢速前进，等 Limit_Centered() 触发
        └─ 触发 -> step 3；超时 2500ms -> 判失败，机构收起
step 3: Arm_Start(POSE_PICK_GROUND)  夹紧 -> 抬起 -> 兜入仓
step 4: 等机构跑完（>3s 判失败）
step 5: 后退 300ms @ 0.30，确认方块在车上 -> 成功
```

**三条安全设计**（这是敢让它上场的原因）：

1. **每个 step 都有硬超时**，卡住不会一直顶着电机（顶着 = 堵转 = 烧驱动/电池）
2. **失败也要收机构**：`finish(0)` 里调 `Arm_Start(POSE_STOW)`，
   绝不张着爪子到处跑
3. **操作手动摇杆立刻中止**

### 2026-10-07 · 为什么慢速靠拢是 0.35 而不是更快

实测对照（每档 10 次）【待回填：补表】：

| 靠拢速度 | 成功 | 失败模式 |
|---|---|---|
| 0.60 | 2/10 | 方块被撞飞出去 |
| 0.45 | 5/10 | 一半被撞飞，一半压不到限位 |
| **0.35** | **7/10** | 主要是斜撞后被弹到侧面 |
| 0.25 | 6/10 | 成功率高但太慢，5 分钟里拿不到几个 |

0.35 是"成功率 × 节奏"的折中。这个参数**必须在实车上重标**，
因为地胶的脏污程度、电池电量都会影响。

### 2026-10-13 · 视觉模块评估与成本决策

如果要上视觉，我们评估过的方案：

| 模块 | 价格 | 优点 | 缺点 |
|---|---|---|---|
| K210（Maix Bit / Dock） | ¥60~90 | 有硬件 KPU，能跑色块/分类，MaixPy 好上手 | 需要额外 5V 供电，体积不小（约 55×30mm） |
| OpenMV | ¥200+ | 生态最好 | 远超预算，且规则允许但成本线不允许 |
| ESP32-CAM | ¥25 | 最便宜 | 算力弱、没有好用的图像处理库、帧率低 |

**结论**：如果做，选 **K210**，但排在中期考核之后。
成本上：官方物资表 353.48 + 必买件 62 + K210 90 ≈ 505 元，
超过推荐线 400 元约 25%。

我们的处理办法是**先不买**，把视觉作为"如果晋级再加"的储备，
并在文档里如实说明。成本规范对新生组的措辞是"**不推荐超过**"而非"不得超过"，
但既然是"不推荐"，能不超就不超。

### 2026-10-13 · 视觉协议：定长帧 + 异或校验

K210 → STM32 的帧（14 字节）：

```
AA 55 cls xL xH yL yH wL wH hL hH areaL areaH chk
```

- `cls`：1 = 白块、2 = 黄块、0 = 没找到
- `x / y`：目标中心像素坐标（画面 320×240，中心 160,120）
- `w / h / area`：色块尺寸与面积（面积用于判断"已经够近了"）
- `chk`：从 cls 到 areaH 全部字节异或，低 8 位

**为什么不用 `\r\n` 做帧尾**：`0x0D` 和 `0x0A` 都可能出现在数据里，
状态机会被带跑，出现"数据错位但还在收"的怪事 —— 这种 bug 新手能查一整天。
定长帧 + 校验和没有这个问题。

**为什么面积比距离更重要**：我们不做测距（标定太麻烦），
直接用色块像素面积判断是否到位（`VISION_NEAR_AREA = 9000`）。
近了面积就大，够了就夹。这是个"够用就行"的简化，
在 V1.3 的 40mm 方块场景下工作得很好（V1.4 改成 30mm，尺寸阈值要按 30mm 重测）。

### 2026-10-14 · 视觉调试流程（写给还没买模块时的自己）

**第 0 步：先不接 STM32。** 用 USB-TTL 把 K210 接到电脑，串口助手看帧。

**第 1 步：抠阈值。** 打开 MaixPy IDE → 工具 → 机器视觉 → 阈值编辑器，
对着实际方块抠出 LAB 阈值，抄进 `vision/k210_find_cube.py` 的 `YELLOW_TH` / `WHITE_TH`。

> ⚠️ **这是视觉 90% 的坑所在**。场地灯一换、一天中的时间一变，
> 阈值就漂。比赛前一定要在**实际场地、实际光照**下重抠一次。

**第 2 步：关自动增益/白平衡。**
```python
sensor.set_auto_gain(False)
sensor.set_auto_whitebal(False)
```
不关的话，画面一亮一暗阈值就漂。

**第 3 步：确认坐标合理。** 画面中心是 (160,120)，
把方块放在正前方，看 x 是不是接近 160。

**第 4 步：接 STM32，看 `app.c` 打出来的 `vis cls=...` 行。**

**第 5 步：调 `VISION_TURN_KP`。** 先给 0.001（很小），
车反应不够再加。给大了车会左右振荡（在目标前画 S 形）。
