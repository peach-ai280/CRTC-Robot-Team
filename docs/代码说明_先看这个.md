## 一句话结论

**你真正要烧进车里的，只有 `firmware/` 一个文件夹。**
其他（`cpp/`、`tools/`、`vision/`）都是给你和同学看、或者在电脑上跑的辅助东西，
**永远不会被装到车上**。

## 三类东西，一眼分清楚

| 文件夹 | 是干嘛的 | 会不会烧到车上 | 你现在要不要管 |
|---|---|---|---|
| **`firmware/`** | 车的大脑。STM32 芯片跑的程序 | ✅ **就是它** | 要（等你焊好线） |
| `cpp/` | 同一套逻辑的 C++ 版本，用来**在电脑上离线试参数** | ❌ 不会 | **现在完全不用管** |
| `tools/` | 电脑上用的工具：编译、烧录、自检、切片 | ❌ 不会 | 要用到 3 个脚本 |
| `vision/` | K210 摄像头的 Python 程序（可选功能） | ❌ 烧到摄像头，不烧车 | **先不管**（K210 还没买） |

## firmware/ 里面，你现在只需要认识 3 个文件

### ★ 1. `firmware/Core/Inc/config.h` —— 调参数的唯一入口

**全车 95% 的调整都在这个文件里改数字，不用碰别的。**

比如：
- 车走偏了 → 改 `SPEED_GAIN_FORWARD` / `SPEED_GAIN_STRAFE`
- 舵机角度不对 → 改 `SERVO_*` 那一堆
- 收集铲要快慢一点 → 改 `AUTO_*` 的超时时间

**改完这个文件，重新编译 + 烧录一次就行。** 别的 .c 文件一行都不用动。

### ★ 2. `firmware/Core/Inc/board.h` —— 接线对照表

**每个硬件接在芯片的哪个脚上，全写在这里。**
你要焊线、查线、怀疑线接错了，就看这个文件。它长这样（示意）：

```
PS2 手柄  DI/DAT  -> PA7
         DO/CMD  -> PA6
电机 PWM          -> PA8/PA9/PA10/PA11 ...
```

**改接线前先看它，别自己发明引脚。**

### ★ 3. `firmware/Core/Src/main.c` —— 主程序

上电先干什么、主循环里一遍遍干什么。你**基本不用改它**，但想知道车在干嘛可以看它。

## 其他 .c 文件分别是干嘛的（不用背，出问题再来查）

| 文件 | 干嘛的 |
|---|---|
| `mecanum.c` | 麦轮数学：你推手柄的方向 → 四个轮子各转多快 |
| `motor.c` | 电机输出：把速度变成 PWM 和方向信号，含死区补偿 |
| `ps2.c` | 手柄通信：读按键和摇杆（**你不用懂协议，照接线表接就行**） |
| `servo.c` | 舵机：给角度、慢慢转过去 |
| `arm.c` | 机械臂动作：取块 / 举升 / 放仓 的整套动作 |
| `auto_task.c` | 半自动：一键收集、一键挑架、一键探洞 |
| `auto_full.c` | 全自动：在上面那套动作之上自动调度 |
| `bsp.c` | 开机初始化（时钟、GPIO、定时器、SPI），**不用改** |
| `sensor.c` | 限位开关 + 电池电压检测 |
| `hal_shim.c` | ★ 我们自己写的底层替代层（官方库下载不到），**绝对不要改** |
| `startup_stm32f103xb.c` | 启动文件，**绝对不要改** |
| `test_motion.c` / `test_arm.c` / `test_vision.c` | 三个测试固件：分别只测底盘 / 只测臂 / 只测摄像头 |

## 你会用到的 3 条命令（现在先记着，装好线再跑）

都在**仓库根目录** `C:\Users\hp\WorkBuddy\CRTC` 执行：

```bat
python tools/build.py full        :: 第 1 步：编译出能烧的文件
python tools/flash.py ps2         :: 第 2 步：先烧"只测手柄"的版本，把 PS2 接对（车不会动）
python tools/flash.py motion      :: 第 3 步：再烧"只测底盘"的版本，确认轮子会转
python tools/flash.py full        :: 第 4 步：底盘没问题了，再烧完整版
```

- **`build.py`** = 编译（把 C 变成芯片能跑的二进制）。没有 make，用这个代替。
- **`flash.py`** = 烧录（把文件写进芯片）。它会自动去找 CubeIDE 自带的烧录器，不用你另装。
- 编译出来有报错 → 跑 `python tools/check_symbols.py` 查缺了什么。

⚠ **顺序别反**：先 `ps2`（只让 STM32 读手柄），再 `motion`（只让轮子转），
最后才上 `full`。直接上 full 出问题你分不清是手柄、底盘还是机械臂的锅。

## 常见疑问

**Q：cpp/ 那套到底要不要学？**
不要。那是我为了在没有硬件的时候验证逻辑写的，装车之后它的唯一价值是「离线试参数」。
**打比赛用的是 `firmware/` 这套 C 版。**
⚠ 两套的参数是重复的两份，改的时候**两边都要改**，所以你现在别碰 cpp，省得改漏。

**Q：那么多 .c 文件我要不要一个个看懂？**
不用。**看懂 `config.h` 就够了**，其他都是被调用的。

**Q：代码里那些 `hal_shim` 是什么，要不要换回官方库？**
不要换。官方 HAL 库我们下载不到，这是我用纯寄存器重写的一层，
函数名字和官方一模一样，所以业务代码一个字没改。**能编译能烧就是对的。**
